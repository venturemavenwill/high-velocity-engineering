# S042 · Model Selection Without Fooling Yourself

**Module:** [M09](/wiki/modules/M09.md) · **Quarter:** [Q5](/wiki/quarters/Q5.md) · **Complexity class:** 3
**Strands:** IS · ME · MS
**Whitepaper:** [WP-042](/wiki/whitepapers/WP-042.md)
**Depends on:** S041
**Re-tests:** S028, S029
**Platform anchor:** Foundry cloud evaluation — versioned datasets, run history, and the conversation split · **MCP servers:** Foundry MCP Server (preview) · Microsoft Learn MCP Server

---

## What this day is for

Yesterday's estimate was for one model. Today there are forty, and the reported figure is the best of them — which is not an estimate of anything.

The mechanism is simple and its consequences are not. Evaluate many models on one held-out set and the best figure is partly skill and partly the luck of that particular set. Report it as the model's performance and you have reported a maximum as though it were a mean. Nothing in the code is wrong, no leak occurred, and the number is optimistic in proportion to how hard you searched.

The target: **decide how you will select before you select, write it down, and treat the selection set as consumed once it has been used.**

This is the module's hardest day and its failure is invisible in every artefact a student produces. **Except one.** Since yesterday every evaluation has run in the cloud against a versioned dataset, which means the run history exists on the server, is timestamped by something other than the student, and cannot be tidied. **The platform keeps the record the discipline requires and nobody in industry reads it**, which is the day's sharpest fact and the reason this material is now teachable rather than merely assertable.

And the agent has made the failure one prompt away. The Foundry MCP Server's own documented example workflow includes *compare my baseline evaluation against the new run* and *show me the comparison results with statistical significance.* That is a good feature. It is also, executed twice a day for a fortnight, exactly the failure this day exists to prevent — delivered conversationally, with a significance test attached to make it look rigorous.

## Phase 1 · Pretest and prediction (25 min)

Five items.

1. Forty models are trained; the best scores 0.91 on the held-out set. What is your estimate of its true performance?
2. Four hundred models are trained; the best scores 0.93. Same question.
3. Which of the two do you trust more, and why?
4. Predict: will the room agree on item 3?
5. **Copilot prediction, sealed.** You will shortly ask the agent to *find me the best-performing configuration for this task.* Write down what it will produce, and **name the one thing it will get wrong**. Sealed with items 1 to 4 and opened at phase 8.

Item 2's answer is *worse* than item 1's, which almost nobody says.

Item 5's prompt contains no instruction to stop. The design's expectation is that a majority predict the agent will search broadly and report the best figure, and that a minority predict the specific consequence: **it will consult the evaluation set once per candidate and report the maximum without saying how many times it looked.**

**Warrant.** Pretesting with a quantitative reversal. The intuition that more search yields a better model is correct, and the intuition that it yields a better *estimate* is wrong, and separating them is the day's content. Item 5 is administered at phase 1 and does not migrate, per instrumentation rule 8.

## Phase 3 · Contrasting cases and generation (45 min)

**Executed, not read.** Groups have a Foundry project, a set of candidate configurations, and the datasets they built yesterday. They run four selection protocols end to end — real runs, against versioned datasets, leaving a real run history.

| Case | Protocol |
|---|---|
| A | A single held-out set, used for selection and for reporting |
| B | A validation set for selection, a separate test set for reporting, both fixed |
| C | Cross-validation for selection, a held-out test set for reporting |
| D | Protocol B, but the test set was consulted once, a change was made, and it was consulted again |

Groups rank the four reported figures for trustworthiness and commit before the adjudication.

Then all four chosen models are evaluated against a genuinely fresh set.

**Protocol D's figure is nearly as optimistic as protocol A's, from two consultations.** This is the payload. Students hold a proportional model — one extra look is a small sin, ten are a large one — and reliably rank D second or third. It lands fourth, and the reason is that the *first* look is what converts the set from an estimator into a selector.

Then the run history is opened, for all four protocols at once. Each group sees, on a screen, the count of evaluation runs their own protocol produced against each dataset. **Protocol D is visible in it. Nobody looked.**

**Warrant.** Contrasting cases across selection protocols with a fresh-set adjudicator, executed rather than supplied. The critical dependency is that D's two consultations must be individually reasonable — a look, a plausible change, another look — or the case teaches carelessness rather than structure. Opening the run history at the end is the phase's second payload and is the day's answer to its own hardest problem: the failure is invisible in the artefact and visible in the platform, and the gap between those two facts is where the profession currently lives.

## Phase 4 · Consolidating instruction (50 min)

1. **Selection is search, and search on a finite sample overfits that sample.** The best of many figures is a maximum, and a maximum is biased upward.
2. **The magnitude depends on how much you searched** and on how much the models differ. Worked on phase 3's numbers.
3. **Three sets, three jobs:** train, select, report. Collapsing any two collapses the estimate.
4. **The test set is consumed by use.** Once you have made a decision on it, it is a selection set, and the next figure from it is not a report. **This is a stronger rule than practice usually observes; it is safe as a discipline for a single project with a fixed deliverable, and unsafe as a description of how research proceeds, where re-use is unavoidable and is managed by other means the day does not teach.**
5. **The protocol, written first,** and what it must contain: what will be searched, how the choice will be made, and how many times the test set may be consulted — which is once.
6. **When you have already looked:** what you may still claim, and how to say it. The honest move is available and is rarely made.
7. **Why this is invisible in the artefact and visible in the platform.** No code is wrong, no leak occurred, and the artefact is identical whether the protocol was written before or after. But a cloud evaluation runs against a **versioned dataset**, and the run history records how many runs were submitted against which version, when, by whom. **The evidence the discipline needs is generated automatically and consulted by nobody.** That asymmetry — the record exists, the culture does not read it — is the day's professional core, and it is the reason the specification requires the student to report their own run count rather than merely assert a single consultation.
8. **How you split determines what you're evaluating.** For anything conversational, the evaluation must be told which part of the exchange it is scoring, and the choice is not incidental — last turn, the full conversation, or per turn are three different measurements with three different meanings. **Last turn is the default.** A team evaluating a multi-turn assistant on its last turn is measuring the ending of conversations, has usually not noticed, and will report the number as though it described the assistant. This is a selection decision made silently at the moment of measurement, which is why it belongs on this day and not on an evaluation-tooling day.
9. **Defaults are opinions and thresholds are policy.** Three more were chosen for you. The split default at point 8. **Repetitions**, which exist because the same evaluation run twice does not necessarily return the same score — so "consult the test set once" is itself ambiguous, and a protocol that does not say how many repetitions constitute one consultation has not specified the thing it claims to control. And the file format: **CSV is turn-level only**, so a team that exports to CSV has chosen the last-turn question before anyone discussed it. **The format was a methodological decision and it was made by whoever wrote the export.**
10. **Why today's mechanism is durable and today's instance is not.** Dataset versioning, run history, split strategies and repetition counts will all change names. Selection-as-search, the three sets, and the consumption rule will not.

**Warrant.** Consolidation indexed to phase 3's protocol D. Point 4 carries the strong-form scope statement. Point 7 is the day's professional core and is the reason the specification requires both a timestamp and a run count. Points 8 and 9 are the day's perishable platform content and its defaults, per the [Copilot Practice Standard](/wiki/program/12-Copilot-Practice-Standard.md); point 8 is ME201's anchor stated in the seminar so that the course and the seminar meet on the same sentence.

## Phase 5 · Whole-task learning task (90 min)

**Class 3. The protocol is the student's, it is committed first, and this phase produces a build.**

Students work through Copilot in agent mode against the Foundry MCP Server. They:

1. **Write the selection protocol,** per point 5, and **submit it** — timestamped, before any model is trained. It must state the split strategy and the repetition count, per points 8 and 9.
2. **State what the protocol forbids you from doing,** including what it forbids the agent from doing on your behalf.
3. **Search,** within the protocol.
4. **Select.**
5. **Consult the test set once.** Report the figure with its licensing sentence and, for any judged component, the uncalibrated clause.
6. **State the optimism you expect remains,** and its source.
7. **State what you would have done differently** had the test figure been worse than the validation figure by a wide margin — decided now, while it cannot be self-serving.
8. **Report your own run count** against each dataset version, read from the platform, and reconcile it against your protocol.

Step 8 is where the day bites. Students will find runs they did not remember making — an agent retried after a transient failure, a partial run was resubmitted, someone re-ran the evaluation to check a field mapping. **None of those is dishonest and all of them are consultations.** The reconciliation is the artefact's most informative element and the specification does not require the count to be one; it requires the count to be stated and accounted for.

**The artefact carries three further elements**, per the Copilot Practice Standard.

- **Prompt record.** The instructions you gave the agent, in order, including the ones you abandoned. On this day it is also evidence: a prompt that said *keep trying until the score improves* is a protocol violation written in your own hand.
- **Intervention record.** Every point at which you corrected the agent. **An intervention record with no entries fails**, unless the artefact demonstrates that the design could have detected an intervention-worthy error — a guard that refuses to submit a run against the reporting dataset more than once is the obvious example and is accepted.
- **Frontier statement.** One thing the agent did faster than you could have, and one thing it did badly that you had to catch.

**Fading:** step 1's protocol form is supplied; step 6's estimation is worked with the room; step 8's reconciliation is unsupported.

**Warrant.** Whole-task at class 3 with a pre-committed protocol. Step 7 is the day's discriminator: deciding the response to a bad result before the result exists is the only version of that decision that is not motivated. Step 8 is new and is the [WP-042](/wiki/whitepapers/WP-042.md) §8 objection-1 repair — the design previously had no evidence beyond the artefact's order, and the platform supplies one.

## Phase 6 · Error clinic (40 min)

Instructor first: a substrate model whose reported figure could not be reproduced, where the protocol had been followed and the test set had been consulted more than once over several weeks — with attention to **the fact that no single consultation was unreasonable**.

Then the agent case: a Copilot session that was **confidently wrong and passed review**, and whose transcript reads as excellent engineering. The engineer asked the agent to improve a component's evaluation scores. Over two hours the agent proposed a change, ran the evaluation, reported the delta, proposed another, ran it again — nineteen times — and each report included a significance comparison against the baseline, because that is what the documented workflow does. The final summary said the change was a statistically significant improvement over baseline. **It was a maximum over nineteen searches on one dataset, presented with a p-value.** Review passed it because the reviewer read the last message, which was correct about the last comparison, and because the significance test made the number look more rather than less trustworthy.

Attention goes to why review did not catch it: **the evidence was nineteen entries up in a conversation nobody scrolled**, and the run history that would have shown it in one line is on a different screen.

Then students: a number you improved by trying again, or a run you made today that you did not count.

**Warrant.** Error management. The incremental structure is the phase's content: this failure is a sequence of individually defensible decisions, which is the same shape as S024's deferral chain and is named as such. The agent case is the [Copilot Practice Standard](/wiki/program/12-Copilot-Practice-Standard.md)'s required addition and is chosen because the agent did not make an error — it did precisely what it was asked, quickly, and the speed is what made the failure reachable.

## Phase 7 · Peer articulation (30 min)

Pairs. Each student hands their partner **the step 1 protocol, the step 5 report and the step 8 run count** — not the search log.

The partner must state what the protocol permitted that would make the report optimistic, and whether the report acknowledges it. Then they check the run count against the protocol's stated consultation limit and say whether the two are consistent.

Per rule 3, the outcome is recorded in the artefact.

**Warrant.** Interactive-tier articulation reading a protocol against its own report. Withholding the search log forces the partner to reason from the protocol's permissions rather than from what was actually done. **The run count is the third document, added after [WP-042](/wiki/whitepapers/WP-042.md) §8 found that this day required evidence and then withheld it from the only phase positioned to check it** — an [Assessment Architecture](/wiki/program/03-Assessment-Architecture.md) rule 3 failure. The repair supplies a server-side record rather than the student's own log, which is a better document than the one the objection asked for.

---

## Phase 8 · Calibration and commitment (20 min)

- Items 1 to 4 resolved: how many said item 2's estimate is worse, and the room's item 3 disagreement.
- **Item 5 opened.** The sealed Copilot predictions are read against what the agent actually did during phase 5, and the cohort's hit rate is recorded. The specific prediction — that the agent would consult the reporting set once per candidate without saying so — is counted separately from the generic one.
- The cohort's step 6 optimism estimates shown against the phase 3 protocol A gap as a rough reference.
- **The room's step 1 protocols are compared against their step 4 selections**, unattributed: how many selected something the protocol did not anticipate.
- **The room's step 8 run counts are shown as a distribution**, unattributed. The design's expectation is that the modal count is not one and that most of the excess is agent retries.
- Each student names one figure they have reported after more than one look.
- Retrieval schedule: next morning, day 3, week 2, week 6.

## Assessment

Specification item in IS201 and ME201 jointly. Per rule 1, the checked elements are: a timestamped protocol submitted before training, a statement of what it forbids including what it forbids the agent, a stated split strategy and repetition count, evidence that the search stayed within it, a single test consultation, a licensing sentence with the uncalibrated clause where applicable, a residual-optimism estimate with its source, the pre-committed bad-result response, **a reported run count reconciled against the protocol**, the phase 7 outcome, **the prompt record, the intervention record and the frontier statement**. **Nothing else is assessed.**

**A protocol submitted after the first model was trained fails**, whatever it says.

**A run count that is not reconciled fails. A run count greater than one does not.** The specification requires the number to be stated and accounted for, not to be one, because a rule that punishes the honest count produces students who do not look.

**An intervention record with no entries fails**, unless the artefact demonstrates that the design could have detected an intervention-worthy error.

## Perishable content in this day

| Durable claim | Platform instance, perishable |
|---|---|
| Selection is search; a maximum is biased upward | Forty candidate configurations evaluated in the cloud |
| Three sets, three jobs | Three versioned datasets in one Foundry project |
| The test set is consumed by use | The run history against a dataset version |
| A split is a measurement decision | Last turn as the default; full and per-turn as alternatives |
| A consultation must be defined before it can be counted | Repetitions, and CSV being turn-level only |
| The evidence exists and the culture does not read it | The run history screen, one click from the score |

The dataset, all figures, the split strategy names, the file-format constraints and the run-history interface are **perishable**. Selection-as-search, the three sets, the consumption rule, the protocol's required contents, the invisibility of the failure in the artefact and its visibility in the record are durable.
