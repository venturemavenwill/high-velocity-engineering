# S011 · What a Representation Makes Cheap

**Module:** [M03](wiki/modules/M03.md) · **Quarter:** [Q2](wiki/quarters/Q2.md) · **Complexity class:** 1
**Strands:** CF · SY · MS
**Whitepaper:** [WP-011](wiki/whitepapers/WP-011.md)
**Depends on:** S003, S007
**Platform anchor:** Microsoft Foundry embedding deployment — `text-embedding-3-small` and `text-embedding-3-large`, called at `POST {endpoint}/openai/v1/embeddings`
**MCP servers:** Microsoft Learn MCP Server (grounding) · Azure MCP Server, started with the **Read only** option set to true

---

## What this day is for

S003 established that a representation discards. That is half the account and the pessimistic half. The other half is that a representation discards **in order to make something cheap**, and the thing it makes cheap is the reason to choose it.

This day completes the pair. The question becomes two questions asked together: *what did this discard, and what did it buy?* A student who asks only the first becomes cautious; a student who asks only the second becomes careless. The programme needs both, permanently, and this is where they are joined.

The fourth representation on the table is an embedding vector produced by a real Foundry deployment. It is here because it is the representation students will use for the rest of the programme and the one they are least likely to interrogate. Before you can measure anything about it you must choose a model, choose a `dimensions` value and choose a similarity function — three decisions the platform makes for you if you do not — and the consequence is the sentence this day exists to install: **similar is a decision somebody made, not a property of text.** Five later days inherit it: [S016](wiki/seminars/S016.md), [S051](wiki/seminars/S051.md), [S056](wiki/seminars/S056.md), [S057](wiki/seminars/S057.md) and [S058](wiki/seminars/S058.md).

The day also opens the S001 sealed prediction P2, at a ten-week gap.

## Phase 1 · Pretest and prediction (25 min)

Students receive one substrate dataset — real, roughly ten thousand records — and **four** representations of it: a hash index, a sorted array, an inverted term index, and a Foundry embedding vector per record.

1. For each representation, name the operation it makes cheapest.
2. For each, name the operation it makes most expensive.
3. Here are five operations a caller performs, with frequencies. Which representation wins?
4. Predict your answer's rank against the measured result.

Item 3 has a non-obvious answer: the representation that wins is not the one that is best at the most frequent operation.

**Copilot prediction, sealed with the rest.** *In phase 5 you will ask Copilot in agent mode to embed a set of records and return the ones most similar to a query. Write down now: which model will it pick, what will it do about `dimensions`, what similarity function will it write, and where will it be wrong?* Opened at phase 8.

**Warrant.** Pretesting with generation. Item 3's non-obviousness is the day's thesis in miniature and is produced before any instruction. The Copilot item is a prediction about an instrument the student will use for three years and has not yet characterised; it sits at phase 1 because instrumentation rule 8 forbids it migrating to phase 5.

## Phase 2 · Cumulative retrieval set (20 min)

Free recall, no notes.

- The S003 common-structure sentence.
- The S007 cost sentence.

**Then: the S001 sealed prediction P2 is opened.**

Students wrote a prediction in week one about their own six-week retention. It is returned to them, and the corresponding retrieval performance from the S007 and S009 sets is laid alongside. Ten minutes, including two minutes of silence before discussion.

**Warrant.** Expanding-interval retrieval, plus the programme's longest-interval calibration event. The P2 opening is placed inside a content day rather than made ceremonial, so that the finding is treated as evidence rather than as a milestone.

## Phase 3 · Contrasting cases and generation (45 min)

**Executed, not read.** Groups receive **five operation mixes** — five different callers, same dataset, same four representations. Three representations are built locally. The fourth is built by calling a real Foundry embedding deployment, once per record, and is paid for in tokens.

For each mix, predict the winner and commit in writing. Then the measurements are taken by the groups themselves, on the real dataset, on real hardware, against the real endpoint.

Four configurations of the embedding representation are run, and each is a case:

| Case | Configuration | What it is meant to expose |
|---|---|---|
| A | `text-embedding-3-small`, `dimensions` omitted | The default is the model's maximum. Nobody chose it. |
| B | `text-embedding-3-large`, `dimensions` omitted | A different vector length for the same text, and no way to compare the two spaces |
| C | `text-embedding-3-large`, `dimensions` set down to case A's length | Same model, same text, shorter vector — and neighbours that move |
| D | Cases A–C scored by raw cosine, then by Azure AI Search's `@search.score` | The ranking is stable and every threshold the room wrote down is now wrong |

**Case D is the payload.** Rooms expect a similarity score to be a similarity. Azure AI Search's documented vector score is `1 / (1 + cosine_distance)`, bounded 0.333 to 1.00 for the cosine metric — a synthetic monotonic transform, not the cosine value, with an inverse function published so you can get the real number back when you need to set a threshold. Discovering this after having written down a threshold is the day's most durable twenty seconds.

Three of the five mix predictions are usually right. Two are not, and they fail for different reasons: one because the frequency-weighted cost was miscalculated, one because a constant factor dominates that nobody modelled. On at least one mix the embedding representation is both the slowest and the wrong answer, which most rooms do not predict.

Task after: **state the rule you were using, and where it broke.**

**Warrant.** Contrasting cases with a measured adjudicator, using the S007 commit-then-reconcile structure on its third application. Five mixes rather than three, because the design needs both failure modes to appear and one mix cannot produce both — the departure from the pattern's two-to-four is deliberate and is defended in [WP-011](wiki/whitepapers/WP-011.md) §4. Cases A–D are configurations of one service rather than four services, which is the form the pattern's executed-cases requirement takes on a representation day.

## Phase 4 · Consolidating instruction (50 min)

1. **The pair, stated once.** A representation discards in order to make something cheap. Ask both halves, always.
2. **Cost is per operation, and choice is per operation mix.** The frequency-weighted sum is the object, not any individual row.
3. **Where the asymptotic account is enough, and where it is not.** It is enough when the mix is dominated by one operation and the sizes are large. It is not enough otherwise, which is most of the time.
4. **Constant factors have physical causes** — layout, locality, indirection. Named here and explained at S016.
5. **Four representations of the substrate dataset,** worked completely: what each discards, what each buys, and for whom. The embedding buys *approximate nearest-neighbour over meaning* and discards exact lookup, order, auditability and the ability to say why two records were judged alike.
6. **What the platform chose for you, on this day, in four places.** *Defaults are opinions and thresholds are policy.* `dimensions` omitted means the model's maximum. `encoding_format` omitted means `float`, not `base64`. Azure AI Search's vector `metric` omitted means `cosine`, not Euclidean or dot product. And the Azure MCP Server's **Read only** start option defaults to **false** — the quarter's anchor is the read-only server and the server is not read-only unless you say so. Four decisions, none made by anyone in this room, all defensible, all changing the answer.
7. **Perishable, and marked.** `text-embedding-3-large` is currently the largest of the three embedding models Foundry sells directly, and **you cannot upgrade between embedding models** — moving from one to another means generating every vector again. That is a migration cost attached to a choice made on day one, and it is the clearest instance in the quarter of a representation decision you cannot cheaply reverse. **Safe** to reason with while these three models are the deployed ones; **unsafe** at any other version, in any other region, or against any model not in this catalogue.
8. **The caller you have not met.** Every choice made without a known mix is a bet in the S007 sense, and should be recorded as one.

**Warrant.** Consolidation indexed to phase 3's five mixes and four cases. Point 2 is the retained sentence and point 4 is the deliberate forward hand-off to M04. Points 6 and 7 are the day's platform layer and are the two the [Durable and Perishable Register](wiki/program/09-Durable-and-Perishable-Register.md) re-checks before every offering. Point 6 is reachable from phase 3 case D rather than asserted, per instrumentation rule 7.

## Phase 5 · Whole-task learning task (90 min)

**The output is a build.** Students take a second substrate dataset with a **real, documented access pattern** from the system's logs, and ship a working "find records like this one" component to a disposable environment, built in Copilot agent mode against the Foundry embedding deployment.

1. **State the operation mix** from the logs, with frequencies.
2. **Predict the cost of four representations** under that mix, in writing, before measuring.
3. **Build.** Direct Copilot to implement the winning representation and a runner that answers the caller's query. Use the Learn MCP Server to ground every platform claim the agent makes; use the Azure MCP Server, read-only, to confirm the deployment you are actually calling exists and is the one you think it is.
4. **Measure** the built component, not a sketch of it.
5. **Reconcile.** Where the prediction was wrong, say which term you mis-modelled.
6. **State what the winning representation discarded,** and name a caller for whom that loss would be disqualifying.

Step 6 joins the day to S003 explicitly and is the module's recurring closing move.

**Artefact elements.** Three, and they are not optional.

- **Prompt record.** The instructions you gave, in order, including the ones you abandoned. Not a transcript.
- **Intervention record.** Every point at which you corrected the agent, and what the correction was. **An empty intervention record fails**, unless the artefact demonstrates that the design could have detected an intervention-worthy error — a similarity assertion the runner can be made to get visibly wrong, and does not.
- **Frontier statement.** One thing the agent did faster than you could have, and one thing it did badly that you caught. Both from this build.

**Faded guidance:** step 1 is worked with the room; step 2's model is supplied for the first representation; step 3's endpoint, deployment name and authentication are supplied.

**Warrant.** Whole-task at class 1 with a real access pattern rather than a stipulated one. Step 5's mis-modelled-term requirement is what converts a wrong prediction into a corrected model rather than into a shrug. The artefact elements are the [Copilot Practice Standard](wiki/program/12-Copilot-Practice-Standard.md)'s, unchanged; the intervention record's fail condition is [S052](wiki/seminars/S052.md)'s sensitivity discipline applied to a build.

## Phase 6 · Error clinic (40 min)

Instructor first: a representation chosen in the substrate for an operation mix that later changed, and the cost of the change — with attention to whether the original choice was recorded as a bet.

**Then the agent case.** A build in which Copilot wrote a cosine-similarity function that divides by the vector norms, called an endpoint whose vectors it had assumed were already unit-normalised, and returned a confident ranking that was subtly wrong — reviewed by two students and passed, because the code was clean, the tests compared floats to floats, and nothing in the output looked unusual. Attention on why review did not catch it: the artefact was *readable*, the failure was *arithmetic*, and no one had a case whose correct answer they knew independently.

Then students: a structure you chose by habit, and what mix it was actually right for.

**Warrant.** Error management, with a disclosure that connects the day's content to S007's bet framing and makes the recording of assumptions the transferable lesson. The agent case is the [Copilot Practice Standard](wiki/program/12-Copilot-Practice-Standard.md)'s required sixth element and is chosen so that the failure is invisible to code review, which is the class of agent error the programme most needs students to expect.

---

## Phase 7 · Peer articulation (30 min)

Pairs. Each student presents their step 6 disqualified caller, and the partner's task is to **argue that the caller is not hypothetical** — to find, in the substrate's actual user base or plausible near future, someone who resembles them.

Where they succeed, the pair states what the system would have to change.

**Warrant.** Interactive-tier articulation with a realism demand. The phase's function is to prevent the disqualified caller from being a rhetorical device.

---

## Phase 8 · Calibration and commitment (20 min)

- Item 4 resolved: prediction rank against measured rank, shown as a distribution.
- **The Copilot prediction opened.** The room's sealed predictions against what the agent actually did — which model, what it did about `dimensions`, what similarity function it wrote, and where it was wrong. The cohort's accuracy is recorded and is this day's entry in the programme's running frontier map, whose reader is next year's cohort via the [Durable and Perishable Register](wiki/program/09-Durable-and-Perishable-Register.md).
- **P2 revisited briefly**: what students now believe about their own retention estimates.
- Each student names one structure choice in their own current work made without a known mix.
- Retrieval schedule: next morning, day 3, week 2, week 6.

## Assessment

Specification item in CF102. The checked elements are: the logged operation mix; the committed cost predictions; the measurements taken from the built component; the mis-modelled-term reconciliation; the discarded-property statement with a named disqualified caller; **the prompt record**; **the intervention record**; and **the frontier statement**.

A prediction that matches the measurement exactly with no model stated fails the specification. An intervention record with no entries fails unless the build demonstrates that an intervention-worthy error would have been detectable.

**Nothing else is assessed.** In particular the agent's own output quality is not assessed, the phase 1 Copilot prediction is not assessed, and phase 3 case D is instruction rather than evidence.

## Perishability register

| Durable claim | Platform instance carrying it |
|---|---|
| A representation discards in order to make something cheap | Four representations of one substrate dataset |
| Cost is per operation; choice is per operation mix | Five measured mixes |
| Constant factors have physical causes | Measured on this hardware, this runtime, these libraries |
| Similar is a chosen metric, not a property of text | `dimensions`, `encoding_format`, `metric` and the `@search.score` transform |
| A representation choice can be expensive to reverse | You cannot upgrade between Foundry embedding models |
| Defaults are opinions | Azure MCP Server **Read only** defaults to false |

The left column is assessed. The right column is the vehicle, is verified before every offering, and is expected to change. Specific hardware characteristics, library implementations, model names, default values, score ranges and MCP tool annotations are all **perishable** and are marked in the day's materials.
