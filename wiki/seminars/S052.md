# S052 · Attention as a Retrieval Operation

**Module:** [M11](/wiki/modules/M11.md) · **Quarter:** [Q6](/wiki/quarters/Q6.md) · **Complexity class:** 4
**Strands:** IS · ME
**Whitepaper:** [WP-052](/wiki/whitepapers/WP-052.md)
**Depends on:** S013, S051
**Re-tests:** S012
**Platform anchor:** Foundry reasoning-model deployments — `reasoning_tokens`, `reasoning_effort` and reasoning summaries · Azure AI Search vector weighting · **MCP servers:** Foundry MCP Server · Microsoft Learn MCP Server

---

## What this day is for

[S013](/wiki/seminars/S013.md) built a hash table: a content-addressed lookup that takes a key, finds an exact match, and returns one value.

Attention is that operation with the exactness removed. A query is compared against every key, the comparisons become weights, and the result is a blend of every value in proportion to how well its key matched. **It is a soft, content-addressed lookup, and the students already own every part of it.**

The mechanism is therefore not the difficulty. The difficulty is that attention produces something that looks like an explanation — a picture showing what the model "looked at" — and that picture is a routing record, not a causal account. Reading it as an explanation is the most widespread error in the surrounding literature and the students will arrive already committed to it.

**And they will arrive committed to it about their own tool.** Every student in the room has spent five quarters reading an agent's stated reasoning before accepting its work. That text is the same class of artefact as an attention map: it is produced by the system, it is about the system, it is usually plausible, and **nothing about it is a cause.** The platform is unusually explicit about this and the day uses its own words. A reasoning deployment's `reasoning_tokens` are counted in `completion_tokens_details` and are described as *hidden tokens that aren't returned as part of the message response content*. What you are shown, if you ask for it, is a **summary** of them — and the documentation records that *even when enabled, reasoning summaries are not guaranteed to be generated for every step/request*, and that attempting to extract the raw reasoning by other means is unsupported and may violate the acceptable use policy. **The thing students read as the model's reasoning is a generated account of a process they are not permitted to see, which is sometimes not generated at all.**

The target: **a routing record is not causal influence, the difference is measurable by intervention, and a weight map or a stated rationale is a source of hypotheses rather than a source of answers.**

## Phase 1 · Pretest and prediction (25 min)

A model output and its attention map over the input are supplied.

1. **What is the model looking at?**
2. **Explain the output using the map.**
3. Here is the same input with **the highest-weighted token replaced by an unrelated token.** The output is unchanged. Now explain it.
4. Predict: across a hundred inputs, how often does replacing the top-attended token change the output?
5. **Copilot prediction, sealed.** You will shortly ask the agent to make a specific change to the substrate's retrieval configuration and to say why. Write down **what its stated reason will be, and whether that reason will be the thing that actually determines the result.** Sealed with items 1 to 4 and opened at phase 8.

Item 3 requires no framework to feel. Item 4's predictions are collected and are checked at phase 8 against the phase 3 intervention rates.

**Warrant.** Pretesting with an intervention reveal. Item 2 invites the reading the day is built to defeat, and item 3 defeats it before any instruction has occurred — which is the only sequence that works, because a student told in advance that attention is not explanation will agree and then continue reading maps as explanations. **Item 5 is the same trap set for the students' own tool** and is the day's contribution to the running frontier map; it is administered here and not later, per instrumentation rule 8. The design's expectation is that most students will predict the agent's stated reason accurately and will still record it as causal, which is the finding the day wants and cannot obtain any other way.

## Phase 2 · Cumulative retrieval set (20 min)

Free recall, no notes.

- [S013](/wiki/seminars/S013.md): what a hash table does, what it costs, and what "content-addressed" means.
- [S012](/wiki/seminars/S012.md): the cost of comparison, and what changes when every item must be compared to every other.
- [S051](/wiki/seminars/S051.md): similar-to-what, and where a notion of similarity comes from.
- **Bridge:** a hash table returns one value for an exact key. **What would a lookup need in order to return a blend of values for an approximate key?**

The bridge is answered by the room, and the answer is the mechanism. A similarity function over keys, a normalisation so the weights sum to one, and a weighted sum of values.

**Warrant.** Expanding-interval retrieval in which the day's central object is *derived by the room from two structures they already hold*, rather than presented. A student who reaches attention from a hash table has an anchor that survives every architectural change; a student handed the formula has a formula.

## Phase 3 · Contrasting cases and generation (45 min)

The phase runs in two arms, and the split between them is disclosed to students at the start, per instrumentation rule 3.

**Arm A — attention maps, demonstrated rather than operated.** Groups receive **one mechanism, four inputs, and four attention maps**, with the ablation results supplied pre-run. Serverless deployments do not expose model internals, so no attention map on this day is produced by the students and none can be. The maps come from a small open-weight model on local hardware and they are shown as worked examples. **Arm A is not assessed.**

- **Input 1** — the map matches causal influence. Reading it works.
- **Input 2** — weight is concentrated on a position that attracts it for structural reasons. Removing that token changes nothing.
- **Input 3** — the map is diffuse, and one low-weight token is decisive.
- **Input 4** — two heads disagree, and the aggregate map is a mixture describing neither.

Groups produce an attribution from each map alone and commit. **Then the ablation results are supplied.** Attributions 2, 3 and 4 are confidently wrong.

**Arm B — stated reasoning, operated.** Groups then run four cases against a real Foundry reasoning deployment through the Foundry MCP Server, requesting a reasoning summary each time. For each they read the summary, write the attribution it supports, and commit — **then run the intervention.**

| Case | Construction | What the intervention does |
|---|---|---|
| **R1** | An input whose summary names a clause | Removing that clause changes the answer. Reading it works. |
| **R2** | An input whose summary dwells at length on one phrase | Removing the phrase changes nothing |
| **R3** | An input whose summary never mentions one clause | Removing that clause changes the answer |
| **R4** | One input, submitted repeatedly at one `reasoning_effort` setting | Nothing is changed, and the summaries differ anyway — and on some requests no summary is returned at all |

**R4 is the payload and it is the case the room does not expect.** Nothing about the input, the deployment or the settings varied. The stated reasoning did. And the absence of a summary on some requests is not a fault to be reported: the documentation states that even when enabled, reasoning summaries are not guaranteed to be generated for every request, and that this is expected behaviour. **An artefact that is sometimes simply not produced cannot be the cause of an output that is always produced.**

Task after: **state what an attention map is evidence of, and state what a reasoning summary is evidence of.** The two answers are the same and the room is asked to notice that.

**Warrant.** Contrasting cases across attribution failures with intervention as the adjudicator, now split so that the arm the platform permits is operated and the arm it does not is demonstrated and excluded from assessment, per the [Copilot Practice Standard](/wiki/program/12-Copilot-Practice-Standard.md). Arm A's input 1 exists so the day is not "maps are useless"; inputs 2, 3 and 4 are the three distinct ways the reading fails, and a day containing only one of them would teach a special case. **Arm B is the day's commitment discharged in its own phase 3**: R1 to R3 reproduce the three failures in the register the students actually work in, and R4 adds a failure the map arm cannot show at all, because a map is deterministic given the input and a summary is not. The two-arm structure is disclosed because a day that concealed which of its cases were run would be running the selection effect it teaches students to detect.

## Phase 4 · Consolidating instruction (50 min)

1. **Attention is a content-addressed lookup with soft matching.** S013's table returns one value for an exact key. Attention returns a convex combination of all values, weighted by query-key similarity. The operation is the same; the exactness is relaxed.

2. **Query, key and value are three projections of the same input,** and that separation is what makes the lookup learnable. What counts as a good match is [S051](/wiki/seminars/S051.md)'s question again — *similar to what* — now answered separately by every head.

3. **The weights are a routing record, not an explanation.** A weight says how much of a value entered the sum. It does not say the output depended on it. The value may be uninformative, redundant with others, or cancelled downstream.

4. **Causal influence is established by intervention.** Ablate, substitute, or patch in a value from a different input, and measure the change. **This is the only attribution this programme accepts**, and it is the same standard [S030](/wiki/seminars/S030.md) set for measurement generally.

5. **An aggregate over heads describes no head.** Averaging maps across components that disagree produces a picture of something that does not exist. This is [S049](/wiki/seminars/S049.md)'s unit-of-analysis rule in a new domain.

6. **Some positions attract weight for structural rather than content reasons.** Their presence must be checked before any map is read, and a map that has not been checked for them cannot be interpreted at all.

7. **The cost is quadratic in sequence length,** because every query is compared to every key. It is also almost perfectly parallel, which is the reason the architecture exists. [S061](/wiki/seminars/S061.md) and [S062](/wiki/seminars/S062.md) spend two days on the consequences.

8. **The same argument holds for stated reasoning, and the platform documents it.** This is point 3 in the register the students work in daily, and it is the day's central platform content.

   A reasoning deployment produces `reasoning_tokens`, counted in `completion_tokens_details`, described as **hidden tokens that aren't returned as part of the message response content**. When you request a reasoning summary you receive a generated account of them, at one of the summary levels the API offers — and **even when enabled, reasoning summaries are not guaranteed to be generated for every step or request.** For the newest models a `preamble` object can carry planning insight before a tool call, and the documentation is equally direct there: **generation of preambles is not guaranteed, though you can encourage the model by instructing it to output its plan.**

   Read that last clause slowly. **You can increase the quantity of stated reasoning by asking for it, without having changed the computation that produces the answer.** That is weight-is-not-influence stated by the vendor, in a configuration parameter, about the artefact your team will quote in code review. The correct treatment of a stated rationale is therefore identical to the correct treatment of a map: it is a routing record, it generates hypotheses, and any causal claim drawn from it must be established by intervening on the input and measuring the output.

9. **Perishable, and marked as such.** `reasoning_effort` takes three named levels on the reasoning models that support it, one of which is excluded on one older model. Summary levels differ by family and one level is unsupported on one series. `preamble` is specific to one generation. **Every one of those facts will move, and none of them is what is assessed.** The durable claim is that the system's account of itself is generated by the system, is not the process, and is not guaranteed to exist.

10. **Defaults are opinions.** Three were chosen for you. **The reasoning summary is off unless you ask for it**, so the ordinary state of every deployment your team runs is one that never explains itself and never says that it is not explaining itself. `reasoning_effort` has a default you did not set, and raising it makes the model spend longer and produce more hidden tokens. And the output-token budget you set **is spent on tokens you never see**, so a request can exhaust its budget on reasoning and return a truncated answer — an outcome that looks like a model limitation and is a configuration one. [S055](/wiki/seminars/S055.md) spends a day on exactly that confusion.

11. **What a routing record is actually good for:** debugging routing, spotting degenerate patterns, and **generating hypotheses to test by intervention.** Three uses, all diagnostic. None explanatory. This holds for the map and for the summary equally, and the day would be doing damage if it produced students who stopped reading either.

**Warrant.** Consolidation indexed to phase 3. Point 1 is the retained anchor. Point 4 sets the standard. **Point 8 is this day's discharge of the [Copilot Practice Standard](/wiki/program/12-Copilot-Practice-Standard.md)'s commitment that S052 is the day on which the agent's stated reasoning is established as a routing record rather than a cause**, and it is placed as a numbered consolidation point rather than an aside because a commitment delivered as a remark is not delivered. Point 9 is the day's perishable platform content and point 10 its required naming of defaults; point 10's third default is a documentation silence in operational form, since nothing published states how often a budget is exhausted this way. Point 11 exists to prevent the day producing students who discard two genuinely useful diagnostic artefacts — which is the overcorrection this material reliably causes.

## Phase 5 · Whole-task learning task (90 min)

**Class 4. The behaviour, the hypothesis and the intervention are the student's. This phase produces a build.**

Students use Copilot in agent mode, through the Foundry MCP Server, to ship a working attribution harness against a real reasoning deployment. They:

1. **State the behaviour to explain** — a specific output, on a specific substrate input, that you care about.
2. **Form a hypothesis** about what the output depends on.
3. **Design the intervention** that would falsify it.
4. **Capture the system's own account** — the reasoning summary for that input — and record what it suggests. *Before step 5.*
5. **Run the intervention.**
6. **Report where the account and the intervention agree and where they diverge, and state what a divergence your intervention could not have detected would look like.**
7. **State what the account was good for, if anything.**
8. **Run one case twice with nothing changed**, and report whether the account was stable and whether it was produced at all.

**Fading:** step 3's intervention design is worked with the room. **Step 2's hypothesis is unsupported.**

**The artefact carries three further elements**, per the Copilot Practice Standard.

- **Prompt record.** The instructions you gave the agent, in order, including the ones you abandoned.
- **Intervention record.** Every point at which you corrected it. **An intervention record with no entries fails**, unless the artefact demonstrates that the harness's own checks would have caught an intervention-worthy error — a check that treats a missing reasoning summary as an expected outcome rather than an error, and reports it, is the obvious example and is accepted.
- **Frontier statement.** One thing the agent did faster than you could have, and one thing it did badly that you had to catch.

**Warrant.** Whole-task at class 4, now shipping a harness rather than reading supplied artefacts. The step 4 before step 5 ordering creates the anchor deliberately, so that a student who reads the account first and intervenes second experiences the pull of its story against the evidence. **Step 8 is new and is the day's cheapest hard finding**: it costs two requests and it is the only step in the module where the artefact under study is non-deterministic, which is what makes the routing-record claim vivid rather than argued.

**Step 6 uses the corrected sensitivity form.** An earlier version of this clause — [S041](/wiki/seminars/S041.md)'s and [S048](/wiki/seminars/S048.md)'s — required a finding to be *found*. [WP-048](/wiki/whitepapers/WP-048.md) §8 conceded that this imports a factual premise which does not always transfer, and that the honest requirement is that the design's sensitivity be stated. **This is the first day to use the corrected form**, per instrumentation rule 5.

## Phase 6 · Error clinic (40 min)

Instructor first: a substrate debugging session in which an attention map was used to justify a change, the change was made, and the behaviour did not move. The dependency was elsewhere. Attention is directed at one point — **the map was correct.** Nothing about it was wrong. The reading was.

Then the agent case, and it is the same failure one register up. A student asked Copilot to fix a retrieval regression. The agent made a change and explained it: it said the regression came from the vector arm dominating the text arm, and it adjusted the vector weight accordingly. **The explanation was coherent, specific, technically literate, and cited a real parameter with a real effect.** The change shipped. The regression did not move, because the cause was a chunking change made the previous week that nobody had connected to it.

Attention goes to why review did not catch it. **The reviewer read the reason, found it plausible, and approved the change on the strength of the reason rather than on the strength of a measurement.** The agent had not lied and had not been careless; it produced an account, and an account is what it produces. The reviewer treated a generated rationale as a derivation. This is item 5's trap, sprung with the students' sealed predictions in the room.

Then students, in threes: a time you explained a system's behaviour from a visualisation, or a time you approved an agent's change because the explanation was good.

**Warrant.** Error management targeting points 3 and 8. The instructor case is chosen because the artefact was accurate, which makes it a reasoning failure rather than a tooling failure. **The agent case is the required addition and is deliberately the same shape**, because the whole argument of point 8 is that the two are one failure, and a clinic that treated them as two would undo it. Both are chosen because the students will produce the same failure with dashboards, profiles, traces and agent rationales for the rest of their careers.

## Phase 7 · Peer articulation (30 min)

Pairs. Each student presents **their step 5 intervention result and the causal claim they drew from it.**

The partner's task: **produce an alternative explanation consistent with the same intervention result.**

Then, together: **which further intervention distinguishes the two?**

Per rule 3, the outcome is recorded in the artefact, including the case where no alternative could be constructed.

**Warrant.** Interactive-tier articulation applying alternative-hypothesis discipline to the day's own preferred method. The phase exists because the day risks replacing one uncritical attribution — reading the map — with another — trusting a single intervention. **No prior remedy in the design fits this failure**, and the structure is new; it is recorded here so that rule 5 can apply it elsewhere.

---

## Phase 8 · Calibration and commitment (20 min)

- Item 4's predicted top-token-replacement rate against the measured rate across phase 3 arm A's inputs.
- Step 4's account against step 5's intervention: **the cohort's divergence rate**, and how many students' step 2 hypotheses survived.
- **Step 8's stability results**, reported as two numbers: how many students' repeated runs produced a different account, and how many produced no account at all.
- How many phase 7 partners produced a viable alternative explanation.
- **Item 5 opened.** The sealed predictions about the agent's stated reason are read against what it actually said and against what the intervention showed. The cohort's hit rate is recorded on both halves separately, because predicting the words is a different skill from predicting whether they were causal.
- Each student names one system behaviour they have explained by looking at a visualisation, and one change they have approved because the explanation was good.
- Retrieval schedule: next morning, day 3, week 2, week 6.

## Assessment

**One specification item**, in IS202. Per [Assessment Architecture](/wiki/program/03-Assessment-Architecture.md) rule 1, the checked elements are: the behaviour; the hypothesis; the intervention design; the system's own account recorded before the intervention; the intervention result; the agreement-and-divergence report with the sensitivity statement; what the account was good for; the repeated-run stability result; the phase 7 alternative explanation with the distinguishing intervention; **the prompt record; the intervention record; and the frontier statement.** **Nothing else is assessed.**

**Phase 3 arm A is not assessed.** Attention maps are demonstrated rather than operated on this day, because serverless deployments do not expose model internals, and the specification does not require a student to produce or interpret one.

**A causal claim supported only by a routing record fails.** This is the day's single hard requirement, and after point 8 it covers both the map and the stated rationale.

**An intervention record with no entries fails**, unless the artefact demonstrates that the design could have detected an intervention-worthy error.

No entrustment judgement. The quarter's is at [S060](/wiki/seminars/S060.md).

**Instrumentation under rule 6.** Two instruments with named response occasions:

- **The step 4-against-step 5 divergence rate** measures whether students can read an account without being captured by it. A low divergence rate is ambiguous — it may mean the accounts were faithful or the interventions were insensitive — and is resolved by the step 6 sensitivity statements. **Response occasion: [S053](/wiki/seminars/S053.md), phase 5, where each student's ablation design is required to state its sensitivity before the ablation is run.**
- **The phase 7 alternative-explanation rate** measures whether the day's own preferred method is being applied uncritically. **Response occasion: [S054](/wiki/seminars/S054.md), phase 3, whose four preference datasets are constructed to admit multiple explanations of the same outcome.**

Item 5's two-part hit rate joins the running frontier map and is read by the following year's cohort through the [Durable and Perishable Register](/wiki/program/09-Durable-and-Perishable-Register.md), per instrumentation rule 9. It is a sample and this day says so, per instrumentation rule 3: one cohort, one substrate, one deployment family, on a task chosen by staff.

## What to take from this day

**The claim to hold.** Attention is [S013](/wiki/seminars/S013.md)'s lookup with the exactness removed: a query compared against every key, the comparisons turned into weights, the values blended in proportion. **A weight map is a routing record and not a causal account, and so is a stated rationale.** Causal influence is established by intervening and measuring.

**What the sources license, and what they do not.** The soft content-addressed lookup, multi-head structure, injected positional information and the quadratic cost are verified at [research/02-technical-foundations/vaswani-attention-is-all-you-need.md](/research/02-technical-foundations/vaswani-attention-is-all-you-need.md). **The day's four attribution claims are not.** Weight against causal influence, intervention-based attribution, structural weight attractors and the incoherence of head-aggregated maps are carried for direction and mechanism only, with no magnitude and no named model. The reasoning-summary behaviour is vendor documentation: it is generated, it is not the hidden tokens, and it is not guaranteed to appear.

**Guidance for your own work.**

- **Record the system's own account before you intervene**, then report where the two diverge.
- **Run one case twice with nothing changed.** An artefact that is sometimes not produced cannot cause an output that always is.
- **Keep reading maps and summaries.** They are good for debugging routing, spotting degenerate patterns and generating hypotheses — diagnostic uses, not explanatory ones.
- **A causal claim resting on a stated rationale is an unsupported inference**, the fifth class on the [Agent Configuration Standard](/wiki/program/13-Agent-Configuration-Standard.md)'s ladder, and writing it there is the discipline.

**Where this is easy to get wrong.** Approving a change because the explanation was coherent, specific and cited a real parameter with a real effect. **The reviewer treated a generated account as a derivation**, and the regression did not move.
