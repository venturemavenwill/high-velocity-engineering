> ## Vocabulary used here without definition
>
> | Term | Meaning |

> | **Learning confound** | The portion of an observed improvement produced by the customer getting better at the task while using the system |

## In plain terms

The number moved. Somebody will say your system moved it, and **in most delivery organisations nobody is assigned the job of establishing that.**

The word *attribution* is doing two jobs in the same document, and the session's first act is to prise them apart.

**Technical attribution** answers *whose consumption was this?* It is a property of the request path. If the request carried a subscription key and the gateway recorded it alongside the tokens consumed, the answer is a fact recorded when the event happened. There is nothing to negotiate.

**Causal attribution** answers *did this system cause that change?* It is a claim about the world, made by a person, on evidence that is always partial.

**The trap is that a document containing excellent technical attribution feels as though it has settled the causal question.** It has not, and the better the telemetry, the stronger the feeling. That is why the session spends half its time building the first kind properly — not because cost accounting is the lesson, but because **the only convincing way to show how little exact consumption data settles is to have exact consumption data in front of you.**

The structural shape underneath is the module's thesis. **The cost side is engineered and the return side is elicited.** Consumption is forecast by named engineers, instrumented by them and refined against telemetry from their own system. Return is chosen by the customer from a menu, measured with instrumentation the customer may not possess, over a period nobody specifies. **The causal step between them is performed by nobody and reviewed by nobody.**

The framework this module teaches from then does something sharper and worse than leaving the step out. **Several of its metric definitions define themselves as the change *attributable to* the system.** A measure defined that way cannot be evidence that the system caused a change, because the attribution has been placed inside the definition. It also poses the confounding question correctly — how would you separate the value of the system from the value of the learning, if a previous solution already exists — **and answers it nowhere.**

So the session teaches four moves and one errand.

**Choose the counter key deliberately**, because that single configuration decision fixes which attribution questions your telemetry can ever answer.

**Find the word.** Search every definition for language that assumes causation and rewrite so the measure describes an observable quantity and the attribution becomes a separate claim. Keep the original beside it. **This is [S054](/wiki/seminars/S054.md)'s discipline in a financial document.**

**List what else could have caused it**, including the customer's own improvement at the task, and downgrade to an association wherever you cannot separate them.

**Disclose the asymmetry** on the page carrying the ratio, not in an appendix.

The errand is the session. **Go and ask a person to own the causal claim.** Most will decline, and a recorded refusal is a stronger artefact than an unowned claim.

## Abstract

This paper defends separating technical from causal attribution as the module's central distinction, and defends requiring a named individual to be responsible for the second while treating a recorded refusal as a satisfactory outcome.

The argument runs in five steps. **First**, the two things called attribution have different epistemic status: one is settled by a record and one is a judgement, and a document that holds both in the same column will import the first's certainty into the second. **Second**, the technical layer is genuinely solvable — a gateway keyed on a chosen counter and emitting dimensioned metrics makes consumption an exact recorded fact — and the session builds it precisely to demonstrate that solving it settles nothing about value. **Third**, a claim whose causal attribution is assigned to nobody is not a claim, and a metric defined as the change attributable to a system presupposes what it is offered to demonstrate. **Fourth**, the customer's own learning is part of most observed improvements and belongs to them, and a claim that absorbs it has taken credit for the customer's competence. **Fifth**, a number's meaning depends on the rules under which it was produced, so the governance of a comparison is part of its evidential weight rather than a side issue.

The session installs a gateway attribution record with a named counter key, dimensioned metrics and a reported unattributed bucket; an attribution statement with a named person, competing explanations, rewritten definitions retaining their originals, a downgrade to association where separation was not achieved, and a disclosure of the instrumentation asymmetry on the page that carries it.

The paper concedes that it teaches responsibility for a question without teaching a method for answering it; that a recorded refusal makes the null outcome cheap; that half the session is spent on a configuration exercise whose direct value is cost accounting; and that the fine-grained attribution it teaches is a surveillance capability whose privacy surface the vendor documentation does not discuss.

## 1. The problem this session must solve

Causation in a delivery engagement is everybody's assumption and nobody's job.

**The mechanism is organisational rather than intellectual.** The engineer measures the system. The customer measures the outcome. The commercial owner assembles both into a claim. **At no point does anybody hold the question of whether the second followed from the first**, because the question belongs to a role that does not exist and would be uncomfortable to occupy if it did.

The result is a claim with no author. It is quoted, it travels, and asked where it came from the answer is a document. **A claim whose attribution is assigned to nobody is not a claim; it is a sentence somebody will use.** The complementary failure is worse: a claim with a contested owner produces an argument about whose number it is, and that argument outlives whatever was being measured.

There is a second problem which is a language failure with a structural cause. **A definition that contains its own attribution cannot be interrogated**, because the interrogation has been foreclosed by the vocabulary. Ask what the measure shows and the answer is the change the system caused. Ask how you know the system caused it and the answer is that the measure shows it. **The circle is short enough that nobody notices they are inside it.**

A third is the one the framework itself raises and abandons. **Something was already in place, and the customer improved at the task while using what you built.** Both contributions are real, both are inside your measurement window, and neither is yours.

And a fourth belongs to this platform generation and did not exist a decade ago. **Consumption attribution has become genuinely easy.** A gateway can record, per request, which subscription and which product incurred which spend. That is a real advance and it creates a new failure: **a value document with a superb cost breakdown and an unowned benefit claim reads as rigorous**, because the rigour is visible on one side and the absence is visible on neither.

The session's response is a counter key, a dimensioned metric, a name, a list, a rewrite and a downgrade.

## 3. Theoretical basis

**3.1 Load profile.** Intrinsic load is moderate and the extraneous load sits almost entirely in the gateway configuration, which is why the workflow is prescriptive to the point of being copyable. The session's real cost is social: it requires a learner to walk into somebody's office and ask them to be accountable for a judgement the organisation has arranged not to make.

**3.2 Why the two attributions are separated first, and why the separation is the whole design.**

This is a distinction the design imposes rather than one any source states, and it is stated as class 3 reasoning. Its warrant is what it explains. **Every failure in §5 is a case of the certainty attaching to one layer leaking into the other**, and once the two are named the failures become recognisable rather than merely regrettable.

The consequence for the artefact is that the two layers occupy adjacent columns rather than adjacent paragraphs. **Prose smooths; a column boundary does not.**

**3.3 Why the counter key is an epistemic decision rather than a configuration detail.**

The gateway documentation states that a token limit can be keyed on **"any counter key, such as subscription key, originating IP address, or an arbitrary key defined through a policy expression"** ([research/06-microsoft-platform/apim-ai-gateway-docs.md](/research/06-microsoft-platform/apim-ai-gateway-docs.md)). That flexibility is presented as a convenience. **It is not: the counter key fixes the set of attribution questions the telemetry can ever answer, for the life of the deployment.** Key on network origin and no question about teams is answerable without a redeployment. The decision is typically made once, early, by whoever wrote the first policy file, and it is not revisited because nothing about it looks like a measurement decision.

The motivating argument is the cleanest reasoning on the page and is worth teaching in its own right. Tokens are the scarce resource; quota is assigned as tokens per minute; and that quota must be distributed "across your model consumers, such as different applications, developer teams, or departments within the company." With one application a limit on the deployment suffices; as the portfolio grows, "you need to make sure that one app doesn't use the whole TPM quota and block other apps from accessing the backends they need." **Generalised: a shared finite resource with no per-consumer accounting will be consumed by whichever consumer is least careful, and nobody will be able to say who.**

Two mechanisms follow. **Prompt-token precalculation** rejects an over-limit request at the edge rather than paying the backend to reject it — a fail-fast design whose transferable lesson is that a limit is cheapest to enforce where the request first becomes legible. And **metric dimensions** are what convert a number into an answer: total consumption tells you the bill, consumption per API per user tells you who to talk to. The documentation notes that logging serves "billing and auditing", **which is the moment observability stops being an operational nicety and becomes a governance requirement.**

**The source's limits are recorded and two of them bear directly on the design.** It is first-party product documentation with a commercial frame: definitional, arguing for a gateway, with **no benchmarks, no latency figures, no cost measurements and no comparison against any alternative.** Capability **varies by service tier**; several named capabilities are **preview**; policy names and attributes drift between revisions, so all configuration shown is illustrative. **And it does not discuss the privacy surface created by logging prompts and completions, despite recommending logging for billing and auditing** — a silence §8's fourth objection treats as the session's own problem rather than the vendor's.

**3.4 Why a name and not a role.** A role is occupied by whoever holds it at the time, and accountability assigned to a role is discharged by the role's existence. **A name can be asked, can answer, and can refuse** — and the refusal is information, which a role cannot produce.

**3.5 Why the original definition is retained beside the rewrite.** Deleting the circular definition removes the evidence that it was circular. **Retaining it makes the rewrite legible as a correction rather than as a preference**, and it lets a later reader see what the organisation had been claiming. This is the same reason this programme's own self-correction record keeps superseded positions visible.

**3.6 Why the learning confound is separated out.** It is the confound most likely to be claimed and least likely to be listed, because claiming it is flattering and listing it is not. **The customer got better at the task while using the system**, and some of that improvement is theirs in a sense that would survive the system's removal. A claim that absorbs it has taken credit for the customer's competence.

**3.7 Why the competing-explanation list must be longer than feels reasonable.**

The production machine-learning literature supplies the structural reason ([research/02-technical-foundations/crowe-machine-learning-production-systems.md](/research/02-technical-foundations/crowe-machine-learning-production-systems.md)). **Entanglement** means changing one thing changes everything, so an upstream difference resurfaces somewhere apparently unrelated. **Configuration** means versions, parameters and lists live where a small error produces radically different behaviour that ordinary software tests will not catch. Together: **the region where an effect is observed is weak evidence about where its cause lives.** A short confounder list assumes the opposite.

The same source supplies the criterion that justifies paying for gateway telemetry at all. Observability is imported from control theory and operationalised as **alertability** — thresholds that make a failure unambiguous — and **actionability** — enough signal to find a cause. **A stream supporting neither is cost rather than observability**, and an undimensioned token metric is precisely that stream, which is why §4.2's workflow spends its effort on dimensions rather than on totals.

**Its limits are heavy and travel with it.** Practitioner guidance from a commercial publisher rather than research: no study design, no comparison group, no measurement that its practices outperform alternatives. Three of its four authors worked at one large vendor, so its default toolchain is that vendor's. Some foundational claims rest on **anonymous practitioner testimony** that cannot be checked. **Every quantity in it is a property of a particular system after a particular run, and no figure from it appears here.**

**3.8 Why the governance of a number is part of its evidential weight.**

Attribution has a public form, and the audit of the leaderboard that had become the de facto public ranking of frontier models is the clearest available demonstration that a number's meaning depends on rules nobody published ([research/03-measurement-evaluation/singh-leaderboard-illusion.md](/research/03-measurement-evaluation/singh-leaderboard-illusion.md)). Some providers could test many variants privately and publish only what they liked, retracting unfavourable results, producing **"biased Arena scores due to selective disclosure of performance results."** **A best-of-many reported as a single draw is a bias with a computable shape rather than merely bad manners.** Battle data was allocated unequally, and models were removed without disclosure, which reshapes the historical record. The conclusion is **"overfitting to Arena-specific dynamics rather than general model quality"**: a rising position is evidence about the platform before it is evidence about the systems on it.

**The transfer is that three governance questions belong beside any quoted comparison** — how many attempts did the producer have, what happened to the ones they did not publish, and who decided what was included — and that their unanswerability is a finding rather than an accusation. The same three questions are the ones somebody should ask about your value claim.

**Its limits:** all allocation figures are external estimates, and the paper says so; the findings are specific to one platform at one time and platform policy can change in response to exactly this kind of audit; it is a critique and a reform proposal rather than a replacement methodology; and **nothing in it establishes that models are not improving or that preference-based evaluation is invalid.** Reading it as leaderboard nihilism misses the argument. **No figure from it is reproduced here.**

**3.9 Why a judge cannot adjudicate an attribution dispute.**

The obvious shortcut when two explanations compete is to have a model decide between them, and the judging literature closes that route with named, mitigable biases ([research/03-measurement-evaluation/zheng-mt-bench-chatbot-arena.md](/research/03-measurement-evaluation/zheng-mt-bench-chatbot-arena.md)). **Position bias** moves a verdict with presentation order. **Verbosity bias** prefers length independent of quality. **Self-enhancement bias** means a judge sharing a family with the system under test is not independent of it. **Limited reasoning** means a judge cannot reliably grade a problem it cannot itself solve — and separating a system's effect from a co-timed reorganisation is not a problem it can solve.

The constructive half is what the session uses: swap presentation order and require consistency, control for length, and **use a judge from a different family than the system under test.** Exercise 6 runs the first of these and is designed to fail, because a verdict that flips on ordering is a more durable lesson than a verdict that holds.

**Its limits:** the work predates current models; its taxonomy has held up better than its figures, **none of which is reproduced here**; and **agreement with human preference is not correctness in any case** — the published benchmark for a judge is agreement with humans at the level humans agree with each other, which is a ceiling rather than a guarantee.

**3.10 Why cost belongs among the criteria rather than in finance's column.**

The evaluation book in this repository places cost and latency alongside domain capability, generation capability and instruction-following as one of four criteria buckets an application should define before it is built ([research/03-measurement-evaluation/huyen-ai-engineering.md](/research/03-measurement-evaluation/huyen-ai-engineering.md)). That placement is the warrant for treating gateway attribution as engineering work rather than as reporting overhead.

The same source supplies the discipline that keeps the causal side honest: **tie the evaluation metric to the business metric and state the usefulness threshold** — what score must the application reach for it to be useful at all. **Every unearned causal claim hides in that mapping**, and writing it as a mapping rather than as a sentence makes the assumption inspectable.

**Its limits:** a practitioner book rather than a study; heavily citational, with a substantial part of its most useful material resting on unattributed interviews; **its illustrative mappings are explicitly illustrations of shape rather than measurements, and no magnitude from it appears here.**

**3.11 Why the asymmetry must be disclosed on the page carrying the ratio.** An appendix disclosure reaches the reader who was already suspicious. **The page that travels is the page that needs the mark**, which is the same argument [S068](/wiki/seminars/S068.md) makes about provenance and the reason both sessions place it identically.

**3.12 Why a recorded refusal satisfies the requirement.** If refusal failed the element, learners would find a compliant name — somebody junior, somebody leaving, somebody who did not understand the question. **Making the refusal a passing outcome removes that incentive**, and the refusal is the honest state of most value claims in this industry.

**3.13 Why the opening items are unscaffolded, and why exercise 3 requires comparison.** The items are a generation phase: learners attempt a problem they have not been taught, fail, and are then taught, with the failed attempt improving later learning even when wrong ([research/04-professional-formation/sinha-kapur-productive-failure.md](/research/04-professional-formation/sinha-kapur-productive-failure.md)). Two conditions bind. **Guidance during generation reduces the failure rate and reduces learning**, which is why the release rule gates §§4, 5 and 9. And **consolidation must explicitly prompt comparison** — side-by-side presentation of a correct and an incorrect answer achieves nothing on its own, and only the instructed-comparison condition learned more. **The evidence is school, university and laboratory work with no adult-professional study in its reference list**, and the extrapolation is conceded at [WP-001](/wiki/whitepapers/WP-001.md) §8.

## 4. Session design and its warrant

The movements run situation, artefact, material, workflow, standard, failure modes, exercises, limits.

**Opening item 1 — who, by name, is responsible for establishing that your system caused the change — is the instrument.** Most answers are a role nobody holds, a team, or a silence, and all three are the finding.

**4.1 Why the material opens on the two-attribution distinction rather than on the corpus defect.** The circular metric is the more entertaining finding and would make a better opening. It is placed second because **a learner who has not separated the two layers reads the circular definition as a writing error rather than as a category error**, and will fix it by choosing better words.

**4.2 Why the workflow builds the layer that settles nothing.**

This is the design's least obvious decision and its most important. Half the session is spent configuring per-consumer quota and dimensioned metrics — work whose direct product is a cost breakdown. **The purpose is not the breakdown. It is to put an exact, unarguable, per-consumer attribution in front of a learner and then ask them what it establishes about value.** The answer is nothing, and it is far more convincing when the learner is holding the artefact than when a paper asserts it.

**The step that carries the most weight is the deliberate unattributed request.** A learner sends one request without the key and finds it in the unattributed bucket, then reports that bucket's share. **A breakdown that sums exactly to the total has silently dropped what it could not classify**, and this is the cheapest available demonstration that the property is normal rather than exceptional. Every supplier dashboard the learner is ever shown has the same property unless it says otherwise.

**4.3 Why the definition search is mechanical.** *Attributable to*, *driven by*, *resulting from*, *enabled by*. **A learner asked to think about circularity will not find it; a learner asked to search for four phrases will**, and the definitions they find will surprise them because those definitions were handed to them and carry institutional authority.

**4.4 Why the confounder list is made worse rather than shorter**, and why the session says so: the list is not an admission, it is the input to everything that follows, and a short list means the analysis has not begun. That inverts the instinct a learner arrives with.

**4.5 Why the errand is an errand.** The learner has to obtain an acceptance or a refusal from a real person. **The refusal is a passing outcome and the session says so before the learner goes**, because otherwise the errand becomes a negotiation the learner is motivated to win. The review then watches what the named person asks for before signing: **that request is the work the statement is still missing**, and it is almost always a way of ruling out one competing explanation that was listed and not addressed.

**4.6 Why the last step attacks the statement rather than improving it**, and why the prompt is constrained. The learner asks the model to argue the change would have occurred anyway *using only the listed explanations*, then to name the one that was omitted. **The constraint is what turns a generic critique into a diagnostic**, and the session requires the learner to record that a model adjudicating between explanations is subject to position and verbosity bias and shares a family with their executor — so it generates candidate objections and never verdicts.

## 5. Predicted failure modes and countermeasures

**Technical attribution mistaken for causal attribution.** The failure the whole design exists against, and the one the workflow makes more likely before it makes it less likely. *Countermeasure:* the two-column artefact, and §4.2's sequencing — build the exact thing, then be asked what it establishes.

**The circular metric surviving.** Likely, because the definitions were handed to the learner and carry institutional authority. *Countermeasure:* the mechanical search, and the [S070](/wiki/seminars/S070.md) element requiring that no definition presuppose attribution and that originals be retained.

**The invisible unattributed bucket.** *Countermeasure:* the deliberate unlabelled request and the requirement to report the bucket's share. **This countermeasure is a single workflow step and §9's prediction 5 predicts it failing to survive into the artefact.**

**The unassigned responsibility.** *Countermeasure:* opening item 1, the errand, and the [S070](/wiki/seminars/S070.md) element that accepts a refusal and rejects a silence.

**The compliant name.** A learner finds somebody who will sign without understanding. *Countermeasure:* partial only — the review watches what the signer asks for, and a signer who asks for nothing is visible. **The design has no stronger defence and §8 concedes it.**

**The short confounder list.** *Countermeasure:* the explicit instruction to make it worse, and the warning sign — your competing-explanation list contains only implausible alternatives.

**The undowngraded claim.** Separation was not achieved and the sentence still asserts causation. *Countermeasure:* the [S070](/wiki/seminars/S070.md) element requiring the downgrade wherever separation was not achieved, and the classification element requiring the claim to be labelled.

**The appendix disclosure.** *Countermeasure:* the standard's requirement that the asymmetry be disclosed on the page carrying the ratio.

## 7. Assessment and evidence generated

No entrustment evidence. **The programme's entrustment decisions begin at [S080](/wiki/seminars/S080.md).**

Five elements of this session's artefact are checked at [S070](/wiki/seminars/S070.md): that attribution is assigned to a named person with their acceptance or refusal recorded; that the technical and causal layers are separated on the page, with the counter key named and the unattributed share reported; that the competing explanations are listed and each is either addressed or explicitly not addressed, with the claim downgraded to association wherever separation was not achieved; that no metric definition presupposes attribution, with every rewritten definition retaining its original beside it; and — through the claim-classification element — that the resulting sentence is labelled causal, associative or descriptive and defended.

**Whether attribution was successfully established is not assessed**, and the specification says so. Only whether somebody is responsible for it and whether the claim was downgraded when it was not.

The elements are written to be checkable on the page rather than as judgements about understanding, which follows the narrative-assessment finding that assessors form their judgement from prose and use scores only to confirm it, and that high-stakes decisions should rest on substantiated reasoning discussed in a group rather than on a single rating ([research/03-measurement-evaluation/govaerts-narrative-assessment.md](/research/03-measurement-evaluation/govaerts-narrative-assessment.md)). **That literature is single-institution medical-education research using mock portfolios and think-aloud methods that cannot capture fast or automatic processing; transfer to engineering assessment is an argument rather than a given.**

## 8. Objections and rebuttals

**Objection 1: the session requires a named person to own a question it does not teach anybody to answer, which is an unfair transfer of risk to whoever signs.**

At its strongest: the learner is sent to obtain an accountability for a judgement that cannot be discharged with the evidence available. **There is no experiment, no control, no counterfactual and no separation method anywhere in this module.** The person who accepts is accepting responsibility for a conclusion nobody can reach, and they will carry it after the engagement ends and the learner has gone. **A design that manufactures accountability without capability has not improved anything; it has found somebody to blame.**

**Conceded, and it is the sharpest objection in the module.** The session teaches ownership of a question and not a method for the question, and it says so in its own limits section. **The rebuttal is narrow and it is about what the named person actually accepts.** The element requires them to own the *establishing*, which includes the legitimate outcome that it was not established and the claim was downgraded — **the accountability is for the honesty of the claim's class, not for the truth of a causal proposition.** That distinction is real and it is thinner than the objection, because in practice a signature will be read as endorsing the number. **The declined fix is to require a separation method — a comparison group, a staged rollout, an interrupted time series — as an element.** It is declined because none is available in most commercial engagements, the source demonstrates none, and requiring one would produce fabricated methods rather than real ones. **The transfer of risk is real and is accepted.**

**Objection 2: a recorded refusal passes the element, so the cheapest route through this session is to ask somebody certain to say no.**

At its strongest: the design has made the refusal a passing outcome to prevent learners finding a compliant signatory. **It has thereby made the null outcome free.** A learner wanting an easy pass asks the busiest, most senior, most obviously unavailable person, records the decline, and satisfies the element without ever attempting a real attribution conversation. **The element then measures whether the learner sent an email.**

**Conceded in part.** The counterweight is that a refusal does not remove the other four elements: the layers still have to be separated, the explanations listed and addressed, the definitions rewritten, and the claim downgraded and defended at [S070](/wiki/seminars/S070.md) — **and a downgraded claim is what the learner then has to report at [S069](/wiki/seminars/S069.md) to somebody who wanted the stronger version.** The refusal is free; its consequences are not. **The declined fix is to require that the refusal include the refuser's stated reason.** It is declined narrowly and it is close to being wrong: recording the reason would strengthen the artefact, and it is declined only because a reason supplied under pressure is unverifiable and would become a field learners write on the refuser's behalf. **The design accepts the gap and records that this is the element it is least confident about.**

**Objection 3: half the session is a cost-accounting configuration exercise, which is finance's work dressed as epistemology.**

At its strongest: the workflow teaches a learner to key a quota, emit dimensions and read a breakdown. **That is useful and it is not this module's subject.** A team already has somebody who does chargeback. The session's actual claim — that consumption attribution settles nothing about value — is a single sentence, and spending half a session's budget to make one sentence memorable is a poor trade against the session's own list of things it does not teach. **A module with no method for causal attribution has spent its time on the part that was never the problem.**

**Partly conceded, and the rebuttal rests entirely on §4.2.** The sentence is not the deliverable; **the felt gap between an exact breakdown and an unowned value claim is**, and a sentence does not produce that gap. The programme's standing commitment is that an instrument must be characterised before its outputs are trusted, and characterising the cheap instrument is the only way to make its silence about the expensive question legible. **The declined fix is to drop the workflow and teach the distinction as prose.** It is declined for the reason [WP-049](/wiki/whitepapers/WP-049.md) §8 gives about the tier-establishment movement and for a sharper one here: **a learner who has not built exact attribution will assume it is harder than it is, and will therefore treat its absence as the reason value claims are weak.** It is not the reason. Value claims are weak even when consumption attribution is perfect, and that is only convincing from the far side of having built it.

**Objection 4: the session teaches learners to build per-user attribution, which is a surveillance capability, from documentation that does not mention privacy.**

At its strongest: the workflow attaches a user-identifying dimension to a metric and logs prompts and completions, and the vendor documentation recommends exactly this for billing and auditing **without discussing the privacy implications at all**. A record fine-grained enough to say which named individual consumed which tokens on which prompts is a personal-data record, subject to retention, access-control and lawful-basis questions the session raises in a comment and does not resolve. **A curriculum that teaches the capability and defers the governance has taught the dangerous half.**

**Conceded, and the concession is not comfortable.** The workflow's code comment flags it, the perishable table carries it, and the session's limits section names the documentation's silence — **but flagging is not resolving, and this paper will not pretend it is.** Two mitigations, neither sufficient. The dimension the workflow makes central is the *team* rather than the individual, and team-level attribution answers the fairness question the gateway exists for without naming a person. And the learner is required to state what the dimension makes answerable **and what it does not**, which is where a thoughtful candidate will raise the retention question themselves. **The declined fix is to forbid user-level dimensions in the workflow.** It is declined because the documentation's own example uses one, and a curriculum that quietly omits the capability leaves a graduate to meet it in production with no framing at all. **The design prefers a named hazard to a hidden one, and accepts that this is a defence of teaching the thing rather than a defence of the thing.**

## 9. Falsifiable predictions and instrumentation

**Prediction 1.** Most candidates will answer opening item 1 with a role, a team or nothing. *Instrument:* the submitted opening answers, coded *named individual* / *role or team* / *absent* by a second reader.

**Prediction 2.** Most candidates will find at least one circular definition in material they were handed. *Instrument:* the count of rewritten definitions per candidate, with the source of each recorded as *supplied* / *authored by the candidate*.

**Prediction 3.** Most attribution requests will be refused. *Instrument:* the attribution statement's outcome field, coded *accepted* / *refused* / *not asked*.

**Prediction 4.** The learning confound will be absent from most competing-explanation lists before the session's fourth material subsection. *Instrument:* the list recorded before and after, with a presence check for a customer-capability entry. **If it is present before, the confounder work at [S066](/wiki/seminars/S066.md) is carrying more than expected and this session's treatment can be shortened.**

**Prediction 5.** A majority of submitted artefacts will report per-consumer figures without reporting the unattributed share, despite having produced it in the workflow. *Instrument:* the artefact, checked for the presence of an unattributed line and for whether the per-consumer figures sum to the stated total. **This predicts the failure of §5's newest countermeasure**, and it is included because a countermeasure whose failure rate is unmeasured is an assumption.

**Prediction 6.** Candidates who ran the order-swap exercise will report a changed verdict at a rate high enough to be noticed, and will nonetheless cite a model's adjudication somewhere in their statement. *Instrument:* the exercise record against the statement text, coded for whether a model verdict appears as evidence. **A confirmation means the demonstration is not transferring past the exercise it lives in.**

**Prediction 7.** Candidates instructed to compare their item-1 answer against the taught criterion will produce named owners or recorded refusals more often than candidates who read the criterion without the comparison prompt. *Instrument:* a within-cohort split on whether exercise 3 was completed. **This is the session's only direct test of the mechanism §3.13 rests on**, and a null result would mean the comparison requirement is ceremony.

## What a learner should take from this paper

**What the design claims.** That two different things are called attribution and only one is settled by a record; that the counter key fixes which questions can ever be answered; that a claim with no named attributor is not a claim; that a definition containing its own attribution forecloses the question it is offered to answer; and that a ratio with an instrumented denominator and an elicited numerator will read as a measurement.

**What the evidence licenses.** Nothing about causation in any engagement. **The framework poses the confounding question correctly and answers it nowhere**, and there is no worked separation anywhere in the corpus. The gateway documentation is definitional and commercially framed, with no performance, cost or comparative data of any kind. The named-person requirement is class 3 and comes from this repository's own reading of the material rather than from the material.

**No magnitude appears anywhere in this paper.** That is a rule of this repository rather than an accident of what was read.

**The concession worth remembering.** You are being taught who owns a question and not how to answer it, using a workflow whose direct product is a cost breakdown. **Expect refusal, record it, and downgrade** — and notice that the person who refused was being asked for something the whole industry has arranged not to supply.

## Evidence status

**Verified in this repository.** That the cost side of the source's value practice is engineered — forecast by engineers, instrumented by engineers, refined against telemetry from their own system — while the return side is elicited: chosen by the customer from a menu, measured with instrumentation the customer may not possess, over a period nobody specifies; that no party is assigned responsibility for establishing that an observed change was caused by the system; that several metric definitions define themselves as the change attributable to the system, presupposing what needed establishing; and that the framework poses the confounding question — how to separate the value and the learning where a previous solution already exists — and answers it nowhere. Recorded at [research/05-fde-craft/microsoft-accelerated-delivery-practice.md](/research/05-fde-craft/microsoft-accelerated-delivery-practice.md), from a complete reading of **access-controlled material that no public reader can check. It contains no figure to reproduce, and none is reproduced.**

That a pipeline elsewhere in the same organisation infers a value, strips its marker, drops the justification at assembly and later grades itself on that value — recorded at [research/05-fde-craft/microsoft-agentic-threat-modelling.md](/research/05-fde-craft/microsoft-agentic-threat-modelling.md), from a complete reading, and load-bearing for the structural parallel this session draws.

That an external audit of a widely used public model leaderboard documents undisclosed private testing with the ability to retract unfavourable results, describes the consequence as biased scores through selective disclosure, reports unequal allocation of comparison data across providers, records undisclosed model removals, and concludes that the effect is overfitting to platform-specific dynamics rather than general model quality — recorded at [research/03-measurement-evaluation/singh-leaderboard-illusion.md](/research/03-measurement-evaluation/singh-leaderboard-illusion.md), from the abstract and listing metadata of an open-access preprint. **The allocation figures are external estimates by the paper's own account, and no figure from it is reproduced here.**

**Cited from general knowledge, not verified here.** That accountability assigned to a role is discharged by the role's existence in a way accountability assigned to a person is not; that a definition containing its conclusion cannot be interrogated within its own vocabulary; that a party using a system improves at the underlying task independently of the system; that a disclosure placed outside the document that circulates reaches only readers already looking for it; and that an aggregate which sums exactly to its stated total has excluded rather than accounted for what it could not classify. **Direction and mechanism only; no magnitude is asserted.**

**Design reasoning with no external warrant.** The separation of technical from causal attribution and its use as the session's organising distinction; the two-column artefact; the requirement that the counter key be recorded with the questions it can and cannot answer; the requirement to report the unattributed share and the deliberate unlabelled request that produces it; the requirement that attribution be assigned to a named individual; the treatment of a recorded refusal as a passing outcome; the mechanical four-phrase search as the method for finding circular definitions; the requirement that originals be retained beside rewrites; the instruction to lengthen rather than shorten the confounder list; the separation of the learning confound as a named category; the requirement that the instrumentation asymmetry be disclosed on the page carrying the ratio; the constrained adversarial prompt; and all seven predictions in §9.

**Grounded in vendor documentation, with its version and its silence recorded.** The gateway capabilities are documented on a first-party overview page recorded at [research/06-microsoft-platform/apim-ai-gateway-docs.md](/research/06-microsoft-platform/apim-ai-gateway-docs.md) and **fetched and read in full**; the individual policy reference pages, the backends page, the unified model API preview, the MCP server pages and the logging how-to were **not fetched**, so every policy behaviour beyond its description on the overview page is unverified. The documentation states that the AI gateway **"extends API Management's existing API gateway"** and **"is not a separate offering"**, with capability availability varying by service tier. It states that quota must be distributed across model consumers such as applications, teams or departments, and that as a portfolio grows one application must not consume the whole allowance. It states that the token limit policy can be keyed on **"any counter key, such as subscription key, originating IP address, or an arbitrary key defined through a policy expression"**, that prompt tokens can be **precalculated at the gateway** so that over-limit requests never reach the backend, and that the remaining allowance can be exposed to downstream policy. It documents metric emission with custom dimensions, and states that logging supports **"billing and auditing"**. It warns that scaling the gateway does not scale the backends, which must be co-located regionally.

**The silences, recorded because they bound what this session may claim.** The page carries **no benchmark, no latency figure, no cost-reduction measurement and no comparison against any other gateway product**; its architectural reasoning is asserted rather than demonstrated. **It does not discuss the latency, cost or operational burden the gateway itself adds.** **It does not discuss the privacy implications of logging prompts and completions, despite recommending logging for billing and auditing** — the surveillance surface is §8's fourth objection and the documentation is no help with it. It does not discuss the correctness risk in semantic caching, where a similarity threshold set loosely returns an answer to a question that was not asked. Several named capabilities, including the unified model API and the Foundry integration, are **preview**. **Policy names, attributes and tier boundaries drift between revisions; all configuration reproduced in the session is illustrative and must be verified against the current reference before use.** **No benefit claim from this documentation is adopted anywhere in this paper, and nothing here should be read as a claim that any product establishes causation** — which is the specific misreading the session exists to prevent. **Nothing in this session or paper is statistical, financial or legal advice.**
