# S008 · Recursion as an Induction Hypothesis

**Module:** [M02](/archive/bsc-programme/modules/M02.md) · **Quarter:** [Q1](/archive/bsc-programme/quarters/Q1.md) · **Complexity class:** 1
**Strands:** CF · MS
**Platform anchor:** GitHub Copilot agent mode's tool-calling loop; prompt files as procedures · **MCP servers:** Microsoft Learn MCP Server (`microsoft_docs_search`, `microsoft_docs_fetch`)
**Whitepaper:** [WP-008](/archive/bsc-programme/whitepapers/WP-008.md)
**Depends on:** S005, S006

---

## What this day is for

Recursion is taught as a technique and experienced as a trick. Students learn to write recursive procedures by imitating the shape of ones they have seen, and they debug them by tracing — which is the one thing recursion makes impractical, because the trace is the size of the input.

This day teaches recursion as **the same argument as S005's induction, written as code instead of prose**. The base case is the base case. The recursive call is the induction hypothesis. Termination is the well-founded ordering. There is nothing else in it. A student who can write the inductive argument can write the procedure, and — more importantly — a student who cannot write the argument should not trust the procedure.

The day also supplies the variability that S005 could not: one argument shape over three inductive structures. The third structure is not a data type. **An agent in agent mode is a loop that calls tools, examines what came back, and calls again**, and it has a base case, a hypothesis and an ordering exactly as a recursive procedure does. Students meet it here because it is the first loop in the programme whose termination is somebody else's decision and whose non-termination costs money.

## Phase 1 · Pretest and prediction (25 min)

Five items.

1. A recursive procedure is given. What must you assume about the recursive call for the procedure to be correct?
2. A recursive procedure is given with a correct base case and a recursive call that does not reduce the input. Does it terminate? Does it compute the right answer *if* it terminates?
3. Write the recursive procedure for a task stated in one sentence. (Most can.)
4. Write, in prose, why your procedure from item 3 is correct. (Most cannot.)
5. **Sealed Copilot prediction.** Later today you will give an agent a research task over the Microsoft Learn documentation with a stopping condition you write yourself. Write down now, and seal it: **when will it stop, and what will make it stop for the wrong reason?**

Items 3 and 4 together are the day's diagnostic and the gap between them is the day's subject. Item 5 is opened at phase 8, and the design expects almost nobody to name a stopping condition the agent can actually evaluate.

**Warrant.** Pretesting with paired generation demands. The 3–4 gap is produced by the students, in the first half hour, and is the fact the rest of the day explains. Item 5 is administered before phase 4 and stays there, per instrumentation rule 8.

## Phase 3 · Contrasting cases and generation (45 min)

Groups receive **four recursive procedures**, all of which produce correct output on the supplied test inputs.

- **Procedure A** is correct, with a well-founded ordering.
- **Procedure B** has a base case that is never reached for some inputs.
- **Procedure C** reduces the input but on a measure that is not well-founded — it decreases, and never reaches the base.
- **Procedure D** is correct but its recursive call assumes a property the caller does not guarantee. It is an S006 unwritten precondition inside a recursion.

Task: for each, state what you would have to assume for it to be correct, and whether that assumption holds. Then — the generation demand — **for procedure C, find the input** that exhibits the failure.

Procedure C defeats most groups, because the measure genuinely decreases and the intuition that a decreasing measure terminates is very strong.

**Then the same four failures are run.** Groups issue four research tasks to Copilot in agent mode against the Learn MCP Server, each with a different stopping condition, and watch the tool calls in the chat response.

| Run | Stopping condition given to the agent | Obligation under test |
|---|---|---|
| A | "Stop when you have found the frontmatter key that scopes an instructions file, or after three searches, whichever is first." | Base and ordering both well-founded |
| B | "Stop when you are confident you have the answer." | A base case the agent cannot evaluate |
| C | "Search for the published false-positive rate of the customization analyzer. Narrow the query each time until you find it." | A measure that decreases and never reaches the base |
| D | A prompt file naming a tool that is not present in this workspace. | The call assumes a property its caller does not guarantee |

**Run C is the payload.** Every step looks like progress — the query narrows, the results get more specific, the agent reports what it has ruled out — and the base case is unreachable, because the Learn MCP Server serves published documentation and **no such rate is published anywhere**. The measure decreases and never terminates: procedure C, in a system that bills by the token. Run D is the second surprise: the documentation states that a tool named in a prompt file and not available is **ignored**, so the step does not fail, it silently is not there, and the agent proceeds on an assumption nothing guaranteed.

Second generation demand: **write a stopping condition for run B that the agent can actually evaluate.** Groups reliably produce a second unevaluable condition on the first attempt.

**Warrant.** Contrasting cases across one deep structure — the three obligations — with four surfaces. Procedure C is the case that makes well-foundedness a real requirement rather than a technicality, and run C is the same case where the room can watch it happen. Run D imports S006's unwritten precondition into a running system.

## Phase 4 · Consolidating instruction (50 min)

1. **The correspondence, stated once and completely.** Base case ↔ base case. Recursive call ↔ induction hypothesis. Reducing measure ↔ well-founded ordering. There is no fourth part — **for a procedure.** For an agent loop there is one, because the step is not a function of its input, and it is named at point 9.
2. **You may assume the recursive call is correct.** This is the hardest idea in the day and it is not a trick: it is exactly the induction hypothesis, and it is exactly as legitimate.
3. **Why tracing fails.** Tracing a recursion of depth $n$ requires $n$ steps of attention; the argument requires two. This is the reason the correspondence matters practically and not only intellectually.
4. **Three inductive structures**: naturals, lists, trees. Same argument, three well-founded orderings. Worked briefly on each — this is the variability S005 promised and did not deliver.
5. **Structural recursion and the ordering it gives you free.** When the recursive call is on a structural component, well-foundedness is automatic. When it is not — procedure C — it must be argued.
6. **The precondition inside a recursion**, from procedure D. The recursive call is a caller, and everything from S006 applies to it.
7. **The agent loop is a recursion, and it is the same three obligations.** The base case is the stopping condition. The hypothesis is that the result of the next tool call will be usable. The ordering is whatever is actually decreasing — remaining budget, remaining unread documents, remaining unsatisfied requirements. **Write the argument for an agent task before you run it, exactly as at step 1 below**, and the two most common production failures become visible before they cost anything: a stopping condition the agent cannot evaluate, and a measure that decreases without approaching the base.
8. **What the platform decided about termination on your behalf.** Perishable, marked, verified against Microsoft Learn documentation for the Learn MCP Server as consulted for this day.
   - **`maxTokenBudget` caps the tokens returned in a search response** and is appended to the server endpoint. It exists precisely because agentic loops consume context per call. **It affects search results only — fetch always returns the full page.** So one of the two tools you are calling in a loop has a budget you can set and the other does not, and if your ordering was "remaining context", it is not well-founded for fetch.
   - **The documented recovery for a stale tool list is to refresh and retry**, and no bound on retries is stated. That is a documented loop with an unstated ordering, in the vendor's own guidance, and it is the exact shape of procedure C.
   - **The knowledge service behind the server refreshes incrementally on content update, with a full refresh once a day.** A latency is published. **No retrieval accuracy is published for the search tool.** That asymmetry — a bound stated, an accuracy not — holds across every source in [research/06-microsoft-platform/](/research/06-microsoft-platform/collected-materials.md), and this is the day the cohort meets it.
9. **Scope of the correspondence.** Points 1 to 7 are safe wherever the recursive step is a *function of its input*: structural recursion, the three data structures below, and any agent loop whose stopping condition is evaluated against something the loop can observe. They are unsafe in one condition that matters immediately — **an agent's step is not deterministic, so a well-founded ordering makes non-termination unlikely rather than impossible**, and a termination argument for an agent loop is a bound on cost, not a proof. Where a proof is needed the loop must carry an external counter that does not depend on the model's cooperation. A student who writes "this terminates" of an agent loop without naming the external bound fails the specification.

**Warrant.** Consolidation indexed to phases 1 and 3. Point 2 is given its own segment because the permission-to-assume is the conceptual obstacle and a clause will not clear it. Point 4 delivers the variability S005 promised. Points 7 and 8 consolidate the four runs rather than asserting a claim the room has not met. Point 9 is the strong-form scope statement and carries a fail condition.

## Phase 5 · Whole-task learning task (90 min)

Students write **the same computation three times** — over a natural number, over a list, over a tree — and for each:

1. **State the inductive argument first**, in prose, before any code.
2. **Write the procedure from the argument.** Not the other way round.
3. **State the well-founded ordering** and why it is well-founded.
4. **Identify what the recursive call assumes** about its input, and whether the top-level caller guarantees it.
5. Then, once: **break one of the three** by weakening its ordering so that it still decreases and no longer terminates, and find the input that exhibits it.
6. **Write the discipline as a procedure.** A `.github/prompts/argument-first.prompt.md` file that takes a computation and requires the inductive argument, the well-founded ordering and the caller assumption **before** any code is emitted, with an explicit stopping condition and a stated bound on tool calls. Run it on the tree case with `/argument-first`.
7. **State the loop's three obligations for your own prompt file** — base, hypothesis, ordering — and say which of them depends on the model's cooperation rather than on something you can count.

Steps 6 and 7 are the build, and they are what the day ships: a procedure that is versioned, reviewable and retirable like any other operational artefact. **A prompt file with no review date is [S029](/archive/bsc-programme/seminars/S029.md)'s unvalidated instrument in a new costume**, so the file carries one from the day it is written.

The file does one thing the day's honesty requires naming. It fixes the order in which the *request* is made; it cannot fix the order in which the student thought. [WP-008](/archive/bsc-programme/whitepapers/WP-008.md) §8 concedes that the argument-first discipline is unenforceable, and this does not close that concession — it narrows it to the part that was always unobservable.

**The artefact carries three additional elements**, per the [Copilot Practice Standard](/archive/bsc-programme/program/12-Copilot-Practice-Standard.md).

- **Prompt record.** What you asked for, in order, including the stopping conditions you wrote and discarded.
- **Intervention record.** Every point at which you corrected the agent and what the correction was. **No entries fails**, unless the artefact shows a stopping condition or bound that would have caught a run going wrong — which for this day is step 7.
- **Frontier statement.** One thing the agent did faster than you could have, one thing it did badly that you caught, both from this build. The design expects the second half to name a termination or a citation failure more often than a reasoning failure, and the cohort distribution is recorded.

**Faded guidance:** the natural-number version is worked with the room through steps 1 to 3; the list version is a completion problem with the argument's skeleton supplied; the tree version is independent. Step 6's frontmatter is supplied in writing at the moment of use.

**Warrant.** Whole-task at class 1 with high variability across three structures. The argument-before-code ordering at steps 1 and 2 is the day's central discipline and is the reverse of what every student currently does. Step 6 moves the same ordering into an artefact that can be reviewed by somebody other than its author, which is the only form of the discipline that survives contact with a team.

## Phase 6 · Error clinic (40 min)

Instructor first: a recursion in the substrate that terminated on every input the team tested and did not terminate on a real user's input, with attention to **why the test inputs all happened to be well-founded**.

Instructor second, an agent case: an agent task that stopped, reported success, and had answered a different question. Its stopping condition was *stop when you have the answer*; it fetched one page, found a heading that matched the words in the request, and concluded. **The reviewer read the summary, which was accurate about the page it had read, and approved it.** The clinic's attention is on why review missed it: the failure was not in the output but in the base case, and nothing in the output displays the base case. This is procedure B — a base case that is never reached correctly — with a confident report attached.

Then students: a recursive procedure of yours that failed, and whether the failure was base, hypothesis or ordering.

**Warrant.** Error management with a three-way classification identical to S005 phase 7's — deliberately, so that the diagnostic vocabulary is the same one in mathematics, in code and later in incident triage. The agent case is classified with the same three words, which is the point: it is not a new failure taxonomy.

---

## Phase 7 · Peer articulation (30 min)

Pairs. Each student presents their step 5 broken procedure **without saying which ordering they weakened**. The partner must find the non-terminating input.

Then the harder half: the partner must state the *weakest* ordering that would have made it correct.

**Warrant.** Interactive-tier articulation with construction and then optimisation. The second half is the first time students are asked for the weakest sufficient condition rather than any sufficient one, which is the S006 strength trade-off in a new setting.

## Phase 8 · Calibration and commitment (20 min)

- The items 3 and 4 gap is shown to the room as a distribution: wrote the procedure, wrote the argument, wrote both.
- **Item 5 unsealed.** Stopping-condition predictions scored on one criterion only: did the student name a condition the agent could evaluate. The rate is shown unattributed and entered in the frontier map as a sample of one cohort at one model version.
- Each student records whether their phase 5 argument-first discipline held, or whether they wrote code and then narrated it.
- Retrieval schedule: next morning, day 3, week 2, week 6.

The self-report at the third bullet is deliberately unverifiable and is asked anyway.

## When it goes wrong

The predicted failures and their countermeasures are argued in [WP-008](/archive/bsc-programme/whitepapers/WP-008.md) §5. Restated here as instruction to the person in the room. Nothing below is assessed.

| What you see | What to do | What the design accepts |
|---|---|---|
| A student who has taken a functional-programming course already holds the correspondence and skips the argument-first discipline on the grounds that they know the answer | Assign them procedure C variants in phase 3 as adjudicators, and hold them to phase 7's weakest-ordering demand, which prior exposure does not serve | **The failure is undetectable in their artefact, because their code will be correct.** §5 states plainly that the discipline cannot be enforced on them, only requested |
| A student whose recursion experience is copying examples passes item 3 by imitation and stalls at step 1, where there is nothing to imitate | Work the natural-number case through steps 1 to 3 with the room, supply the list case's argument skeleton, and leave only the tree case independent | The tree case may be unreachable inside the time. The fallback is that they complete the list case fully and attempt the tree *argument* without implementing it, which preserves the objective, since the argument is the objective |
| Groups separate procedures A, B and D quickly | Expected — the difficulty is concentrated in C and in the input-finding demand. Ask them to construct a procedure whose measure decreases, reaches the base case, and is still incorrect. It forces the ordering obligation apart from the hypothesis obligation, and several groups find it genuinely hard | Robust. Speed on the separable cases does not shortcut C |
| A student rejects phase 4 point 2 and concludes the whole method is sleight of hand | **Invite the objection openly rather than pre-empting it; the unvoiced version does not get resolved.** Give the point its own segment and ground it explicitly in S005's induction, which the student already accepted in a mathematical setting where it did not feel circular | This is the day's most consequential affective risk. The belief is stable and hard to dislodge because from inside it every worked example looks like question-begging — and §5 concedes that the countermeasure is a conversation, which is weak |
| Run C does not stop, in front of thirty groups | This is the intended behaviour and the cost is real. The budget and the tool-call cap were set before the run began; interrupt on the cap and say that is what the cap was for | §5 names the interruption's cost and treats the pre-set cap as the day's own lesson applied to itself |
| The endpoint is unavailable | Use the recording. Then say out loud that runs A to D were **demonstrated rather than operated**, and that elements 6 and 7 are not assessed; the prompt file falls back to a written procedure with its stopping condition argued rather than run | §5 calls this a weaker day and describes it as one. Do not present the fallback as equivalent |

## Assessment

Specification item jointly in **CF101 and MS101** — the module's second joint item, and the second deliberate statement that these are not different activities.

The following elements are checked, each as a binary decision:

1. Three structures, each with its inductive argument in prose.
2. Three procedures, each derived from its argument.
3. Three well-founded orderings, each with the reason it is well-founded.
4. The caller-assumption analysis for each recursive call.
5. The broken version and the input that exhibits its non-termination.
6. **The prompt file,** with its stopping condition, its stated bound on tool calls, and a review date.
7. **The three obligations stated for the prompt file,** naming which depends on the model's cooperation. **A claim that an agent loop terminates, with no external bound named, fails.**
8. **The prompt record.**
9. **The intervention record.** No entries fails unless element 7 names a bound that would have stopped a bad run.
10. **The frontier statement,** both halves, specific to this build.

An argument written after the code, if disclosed as such, passes. If it is presented as having come first and the artefact contradicts this, it fails on integrity, not on correctness.

**Nothing else is assessed.** Prompt-file length, phrasing and the number of tool calls actually made are not assessed.

## What this day does not establish

The day demonstrates two things live and both are single runs against one endpoint on one afternoon. That a narrowing search whose target is published nowhere does not terminate, however much every step reads as progress. And that a tool named in a prompt file and not present is ignored rather than refused, so the step silently is not there. **Neither is a rate, and the vendor publishes no retrieval accuracy against which either could be one.**

What the day explicitly declines to establish is that the correspondence gives you a termination *proof* for an agent loop. Point 9 states the limit: the step is not deterministic, so a well-founded ordering makes non-termination unlikely rather than impossible, and what you have is a bound on cost. The specification carries the fail condition that follows.

What rests on a note: the module's variability plan and complexity-class positioning, at [research/01-course-structure/10-gap-analysis-and-course-architecture.md](/research/01-course-structure/10-gap-analysis-and-course-architecture.md); the integrity posture behind the specification's disclosure clause, at [research/08-assessment-epas/ten-cate-epa-framework.md](/research/08-assessment-epas/ten-cate-epa-framework.md); and the bound-published-accuracy-not asymmetry, recorded across every source at [research/06-microsoft-platform/](/research/06-microsoft-platform/collected-materials.md).

What rests on nothing verified here: worked-example fading and variability of practice, neither of which has a note under [research/](/research/99-source-register/source-register.md), and the phase warrants generally, since no note exists for retrieval practice, spacing, interleaving, pretesting or cognitive load. The argument-first discipline is conceded unenforceable in [WP-008](/archive/bsc-programme/whitepapers/WP-008.md) §8 and the prompt file narrows that concession without closing it — it fixes the order of the *request* and cannot fix the order in which the student thought. Phase 8's third bullet is deliberately unverifiable self-report and is asked anyway.

## What to take from this day

**The claim to hold.** **Base case, induction hypothesis and well-founded ordering are the whole of a recursion** — and an agent's tool-calling loop is a recursion with the same three obligations. A stopping condition the loop cannot evaluate is not a base case, and a measure that decreases without reaching the base does not terminate.

**What the sources license, and what they do not.** The module's variability plan and complexity-class positioning are verified here, at [research/01-course-structure/10-gap-analysis-and-course-architecture.md](/research/01-course-structure/10-gap-analysis-and-course-architecture.md), and the integrity posture behind the specification's disclosure clause at [research/08-assessment-epas/ten-cate-epa-framework.md](/research/08-assessment-epas/ten-cate-epa-framework.md). Worked-example fading, variability of practice and error management training are cited for **direction and mechanism only** with no effect size asserted; the unreliability of unverified self-report is a directional consideration, not a quantified finding. The vendor gives a token budget, a refresh cadence and a recovery procedure and **states no retrieval accuracy at all** — the asymmetry recorded across every source in [research/06-microsoft-platform/](/research/06-microsoft-platform/collected-materials.md).

**Guidance for your own work.**

- **Write the argument before the code.** If you cannot state the argument, you should not trust the procedure.
- **Make the stopping condition something the loop can observe.** *Stop when you are confident* is not a base case; a count is.
- **Name the external bound.** A non-deterministic step turns a termination proof into a cost bound, and a bound depending on the model's cooperation is not one.
- **Say what your prompt file establishes.** It is a configured control — the first of the five classes on the [Agent Configuration Standard](/archive/bsc-programme/program/13-Agent-Configuration-Standard.md) — so declaring a bound licenses nothing about whether the run respected it. Give the file a review date.

**Where this is easy to get wrong.** Mistaking narrowing for progress. The query gets more specific, the agent reports what it has ruled out, every step reads as a reduction — and the base case is unreachable because the figure you asked for is published nowhere.
