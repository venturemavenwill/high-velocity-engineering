# S011 · What a Representation Makes Cheap

**Module:** [M03](/archive/bsc-programme/modules/M03.md) · **Quarter:** [Q2](/archive/bsc-programme/quarters/Q2.md) · **Complexity class:** 1
**Strands:** CF · SY · MS
**Whitepaper:** [WP-011](/archive/bsc-programme/whitepapers/WP-011.md)
**Depends on:** S003, S007
**Platform anchor:** Microsoft Foundry embedding deployment — `text-embedding-3-small` and `text-embedding-3-large`, called at `POST {endpoint}/openai/v1/embeddings`
**MCP servers:** Microsoft Learn MCP Server (grounding) · Azure MCP Server, started with the **Read only** option set to true

---

## What this day is for

S003 established that a representation discards. That is half the account and the pessimistic half. The other half is that a representation discards **in order to make something cheap**, and the thing it makes cheap is the reason to choose it.

This day completes the pair. The question becomes two questions asked together: *what did this discard, and what did it buy?* A student who asks only the first becomes cautious; a student who asks only the second becomes careless. The programme needs both, permanently, and this is where they are joined.

The fourth representation on the table is an embedding vector produced by a real Foundry deployment. It is here because it is the representation students will use for the rest of the programme and the one they are least likely to interrogate. Before you can measure anything about it you must choose a model, choose a `dimensions` value and choose a similarity function — three decisions the platform makes for you if you do not — and the consequence is the sentence this day exists to install: **similar is a decision somebody made, not a property of text.** Five later days inherit it: [S016](/archive/bsc-programme/seminars/S016.md), [S051](/archive/bsc-programme/seminars/S051.md), [S056](/archive/bsc-programme/seminars/S056.md), [S057](/archive/bsc-programme/seminars/S057.md) and [S058](/archive/bsc-programme/seminars/S058.md).

The day also opens the S001 sealed prediction P2, at a ten-week gap.

## Before you run this day

**Materials to prepare.** None of the following exists in this repository. All of it must be built before the day runs, and none of it should be improvised on the day.

- **The module substrate dataset** — real, roughly ten thousand records — with four representations built over it: a hash index, a sorted array, an inverted term index, and one Foundry embedding vector per record. The dataset persists across M03 and [S012](/archive/bsc-programme/seminars/S012.md) assumes it, so build it once and keep it.
- **Cached embedding vectors for that dataset**, generated before the day. This is not an optimisation. It is the stated fallback for an endpoint failure, and without it a single throttled deployment stops phase 3 for everyone at once.
- **The five pretest items**: cheapest and most expensive operation per representation, the five-operations-with-frequencies item whose answer is *not* the representation best at the most frequent operation, and the rank prediction.
- **Five operation mixes** for phase 3, constructed so that three are usually predicted correctly, one fails because the frequency-weighted cost was miscalculated, one fails because an unmodelled constant factor dominates, and on at least one the embedding representation is both the slowest and the wrong answer.
- **A reserve sixth mix**, in which two adjacently ranked representations swap under a small frequency change. Used only if a group predicts all five; it must exist beforehand.
- **A second substrate dataset carrying a real, documented access pattern from the system's logs**, for phase 5. The mix must be derivable from the logs rather than stipulated, which is what makes step 1 workable with the room.
- **The phase 6 clinic pair**: the instructor's own disclosure of a structure choice whose mix later changed, and the agent case — a generated cosine function dividing by the norms against an endpoint whose vectors were already unit-normalised, together with the review that passed it. Both are described on this page and neither is written down anywhere in this repository.
- **The supplied apparatus for phase 5**: endpoint, deployment name and credential, plus the worked cost model for the first representation at step 2.
- **A known-answer similarity case**, so that the intervention record's exemption route is real — a similarity assertion whose correct answer is established independently of the code that produces it.

**Tooling and access to verify beforehand.**

- A Foundry embedding deployment reachable at `POST {endpoint}/openai/v1/embeddings`, with both `text-embedding-3-small` and `text-embedding-3-large` deployed. Phase 3 cases A to C need both.
- **A second deployment, held by you.** [WP-011](/archive/bsc-programme/whitepapers/WP-011.md) §5 requires it, and requires the phase 5 dataset to be small enough to stay well inside one deployment's per-minute quota.
- The Microsoft Learn MCP Server, and the Azure MCP Server **started with Read only set to true**. The option defaults to false, and phase 4 point 6 uses the fact that somebody had to set it.
- Copilot agent mode, and a disposable environment the phase 5 component can be shipped into.

The endpoint is the only item on this list that is not yours. Verify it on the morning, not the week before.

**What is assumed to exist from earlier days.**

- **The sealed P2 predictions from [S001](/archive/bsc-programme/seminars/S001.md), retrievable and matchable to individual students, together with the cohort's S007 and S009 retrieval results to lay alongside them.** This day is where P2 is opened at a ten-week gap, and it is the programme's first long-interval calibration measurement. If the sealed predictions cannot be retrieved, phase 2's second half cannot run at all. Confirm retrievability before planning anything else about this day.
- The S003 interrogative habit and the S007 bet framing. Both are used and neither is re-taught.
- Copilot agent mode in students' hands since Q1, used for construction and not yet characterised as an instrument.
- No experience of measuring anything, and no experience of a service call. Both are first here, which is why the apparatus is supplied entire.

**If a prerequisite is missing.**

- *The endpoint is unavailable, throttled or misconfigured.* Groups proceed on the cached vectors and record the failure as an observation; switch to the second deployment if the fault is yours rather than the service's. State the sample size out loud, because a student whose calls failed will otherwise draw a conclusion about platform reliability from one afternoon, and this day has no framework for that until [S027](/archive/bsc-programme/seminars/S027.md).
- *A group predicts all five mixes.* Hand them the reserve sixth mix and ask them to locate the crossover.
- *The P2 predictions cannot be retrieved.* [WP-011](/archive/bsc-programme/whitepapers/WP-011.md) states no fallback, and none is invented here. Treat it as a reason to move the day rather than to improvise around it.

## Phase 1 · Pretest and prediction (25 min)

Students receive one substrate dataset — real, roughly ten thousand records — and **four** representations of it: a hash index, a sorted array, an inverted term index, and a Foundry embedding vector per record.

1. For each representation, name the operation it makes cheapest.
2. For each, name the operation it makes most expensive.
3. Here are five operations a caller performs, with frequencies. Which representation wins?
4. Predict your answer's rank against the measured result.

Item 3 has a non-obvious answer: the representation that wins is not the one that is best at the most frequent operation.

**Copilot prediction, sealed with the rest.** *In phase 5 you will ask Copilot in agent mode to embed a set of records and return the ones most similar to a query. Write down now: which model will it pick, what will it do about `dimensions`, what similarity function will it write, and where will it be wrong?* Opened at phase 8.

**Warrant.** Pretesting with generation. Item 3's non-obviousness is the day's thesis in miniature and is produced before any instruction. The Copilot item is a prediction about an instrument the student will use for three years and has not yet characterised; it sits at phase 1 because instrumentation rule 8 forbids it migrating to phase 5.

## Phase 3 · Contrasting cases and generation (45 min)

**Executed, not read.** Groups receive **five operation mixes** — five different callers, same dataset, same four representations. Three representations are built locally. The fourth is built by calling a real Foundry embedding deployment, once per record, and is paid for in tokens.

For each mix, predict the winner and commit in writing. Then the measurements are taken by the groups themselves, on the real dataset, on real hardware, against the real endpoint.

Four configurations of the embedding representation are run, and each is a case:

| Case | Configuration | What it is meant to expose |
|---|---|---|
| A | `text-embedding-3-small`, `dimensions` omitted | The default is the model's maximum. Nobody chose it. |
| B | `text-embedding-3-large`, `dimensions` omitted | A different vector length for the same text, and no way to compare the two spaces |
| C | `text-embedding-3-large`, `dimensions` set down to case A's length | Same model, same text, shorter vector — and neighbours that move |
| D | Cases A–C scored by raw cosine, then by Azure AI Search's `@search.score` | The ranking is stable and every threshold the room wrote down is now wrong |

**Case D is the payload.** Rooms expect a similarity score to be a similarity. Azure AI Search's documented vector score is `1 / (1 + cosine_distance)`, bounded 0.333 to 1.00 for the cosine metric — a synthetic monotonic transform, not the cosine value, with an inverse function published so you can get the real number back when you need to set a threshold. Discovering this after having written down a threshold is the day's most durable twenty seconds.

Three of the five mix predictions are usually right. Two are not, and they fail for different reasons: one because the frequency-weighted cost was miscalculated, one because a constant factor dominates that nobody modelled. On at least one mix the embedding representation is both the slowest and the wrong answer, which most rooms do not predict.

Task after: **state the rule you were using, and where it broke.**

**Warrant.** Contrasting cases with a measured adjudicator, using the S007 commit-then-reconcile structure on its third application. Five mixes rather than three, because the design needs both failure modes to appear and one mix cannot produce both — the departure from the pattern's two-to-four is deliberate and is defended in [WP-011](/archive/bsc-programme/whitepapers/WP-011.md) §4. Cases A–D are configurations of one service rather than four services, which is the form the pattern's executed-cases requirement takes on a representation day.

## Phase 4 · Consolidating instruction (50 min)

1. **The pair, stated once.** A representation discards in order to make something cheap. Ask both halves, always.
2. **Cost is per operation, and choice is per operation mix.** The frequency-weighted sum is the object, not any individual row.
3. **Where the asymptotic account is enough, and where it is not.** It is enough when the mix is dominated by one operation and the sizes are large. It is not enough otherwise, which is most of the time.
4. **Constant factors have physical causes** — layout, locality, indirection. Named here and explained at S016.
5. **Four representations of the substrate dataset,** worked completely: what each discards, what each buys, and for whom. The embedding buys *approximate nearest-neighbour over meaning* and discards exact lookup, order, auditability and the ability to say why two records were judged alike.
6. **What the platform chose for you, on this day, in four places.** *Defaults are opinions and thresholds are policy.* `dimensions` omitted means the model's maximum. `encoding_format` omitted means `float`, not `base64`. Azure AI Search's vector `metric` omitted means `cosine`, not Euclidean or dot product. And the Azure MCP Server's **Read only** start option defaults to **false** — the quarter's anchor is the read-only server and the server is not read-only unless you say so. Four decisions, none made by anyone in this room, all defensible, all changing the answer.
7. **Perishable, and marked.** `text-embedding-3-large` is currently the largest of the three embedding models Foundry sells directly, and **you cannot upgrade between embedding models** — moving from one to another means generating every vector again. That is a migration cost attached to a choice made on day one, and it is the clearest instance in the quarter of a representation decision you cannot cheaply reverse. **Safe** to reason with while these three models are the deployed ones; **unsafe** at any other version, in any other region, or against any model not in this catalogue.
8. **The caller you have not met.** Every choice made without a known mix is a bet in the S007 sense, and should be recorded as one.

**Warrant.** Consolidation indexed to phase 3's five mixes and four cases. Point 2 is the retained sentence and point 4 is the deliberate forward hand-off to M04. Points 6 and 7 are the day's platform layer and are the two the [Durable and Perishable Register](/archive/bsc-programme/program/09-Durable-and-Perishable-Register.md) re-checks before every offering. Point 6 is reachable from phase 3 case D rather than asserted, per instrumentation rule 7.

## Phase 5 · Whole-task learning task (90 min)

**The output is a build.** Students take a second substrate dataset with a **real, documented access pattern** from the system's logs, and ship a working "find records like this one" component to a disposable environment, built in Copilot agent mode against the Foundry embedding deployment.

1. **State the operation mix** from the logs, with frequencies.
2. **Predict the cost of four representations** under that mix, in writing, before measuring.
3. **Build.** Direct Copilot to implement the winning representation and a runner that answers the caller's query. Use the Learn MCP Server to ground every platform claim the agent makes; use the Azure MCP Server, read-only, to confirm the deployment you are actually calling exists and is the one you think it is.
4. **Measure** the built component, not a sketch of it.
5. **Reconcile.** Where the prediction was wrong, say which term you mis-modelled.
6. **State what the winning representation discarded,** and name a caller for whom that loss would be disqualifying.

Step 6 joins the day to S003 explicitly and is the module's recurring closing move.

**Artefact elements.** Three, and they are not optional.

- **Prompt record.** The instructions you gave, in order, including the ones you abandoned. Not a transcript.
- **Intervention record.** Every point at which you corrected the agent, and what the correction was. **An empty intervention record fails**, unless the artefact demonstrates that the design could have detected an intervention-worthy error — a similarity assertion the runner can be made to get visibly wrong, and does not.
- **Frontier statement.** One thing the agent did faster than you could have, and one thing it did badly that you caught. Both from this build.

**Faded guidance:** step 1 is worked with the room; step 2's model is supplied for the first representation; step 3's endpoint, deployment name and authentication are supplied.

**Warrant.** Whole-task at class 1 with a real access pattern rather than a stipulated one. Step 5's mis-modelled-term requirement is what converts a wrong prediction into a corrected model rather than into a shrug. The artefact elements are the [Copilot Practice Standard](/archive/bsc-programme/program/12-Copilot-Practice-Standard.md)'s, unchanged; the intervention record's fail condition is [S052](/archive/bsc-programme/seminars/S052.md)'s sensitivity discipline applied to a build.

## Phase 6 · Error clinic (40 min)

Instructor first: a representation chosen in the substrate for an operation mix that later changed, and the cost of the change — with attention to whether the original choice was recorded as a bet.

**Then the agent case.** A build in which Copilot wrote a cosine-similarity function that divides by the vector norms, called an endpoint whose vectors it had assumed were already unit-normalised, and returned a confident ranking that was subtly wrong — reviewed by two students and passed, because the code was clean, the tests compared floats to floats, and nothing in the output looked unusual. Attention on why review did not catch it: the artefact was *readable*, the failure was *arithmetic*, and no one had a case whose correct answer they knew independently.

Then students: a structure you chose by habit, and what mix it was actually right for.

**Warrant.** Error management, with a disclosure that connects the day's content to S007's bet framing and makes the recording of assumptions the transferable lesson. The agent case is the [Copilot Practice Standard](/archive/bsc-programme/program/12-Copilot-Practice-Standard.md)'s required sixth element and is chosen so that the failure is invisible to code review, which is the class of agent error the programme most needs students to expect.

---

## Phase 7 · Peer articulation (30 min)

Pairs. Each student presents their step 6 disqualified caller, and the partner's task is to **argue that the caller is not hypothetical** — to find, in the substrate's actual user base or plausible near future, someone who resembles them.

Where they succeed, the pair states what the system would have to change.

**Warrant.** Interactive-tier articulation with a realism demand. The phase's function is to prevent the disqualified caller from being a rhetorical device.

---

## Phase 8 · Calibration and commitment (20 min)

- Item 4 resolved: prediction rank against measured rank, shown as a distribution.
- **The Copilot prediction opened.** The room's sealed predictions against what the agent actually did — which model, what it did about `dimensions`, what similarity function it wrote, and where it was wrong. The cohort's accuracy is recorded and is this day's entry in the programme's running frontier map, whose reader is next year's cohort via the [Durable and Perishable Register](/archive/bsc-programme/program/09-Durable-and-Perishable-Register.md).
- **P2 revisited briefly**: what students now believe about their own retention estimates.
- Each student names one structure choice in their own current work made without a known mix.
- Retrieval schedule: next morning, day 3, week 2, week 6.

## When it does not work

These are [WP-011](/archive/bsc-programme/whitepapers/WP-011.md) §5's predicted failure modes, restated as instruction to the person in the room. The whitepaper is the authority; where this section and §5 diverge, §5 is right.

**A student predicts phase 3 correctly, including the constant-factor mix, and finds phase 5 routine.** They have performance-engineering experience and are treating the day as confirmation, which means they will skip step 5's model articulation — the one part that would make their intuition transferable to someone else. Do not correct them directly. Require their phase 3 group to produce the *rule*, which exposes an accurate predictor who cannot state one, and assign them the hardest disqualified-caller cases in phase 7.

**A student is stuck on the apparatus rather than on the content.** They have never measured anything and are meeting unfamiliar data, unfamiliar instrumentation and an unfamiliar failure mode simultaneously. The apparatus is supplied and pre-verified for this reason, step 1 is worked with the room, step 2's model is supplied for the first representation, and the dataset persists across the module. When a measurement anomaly appears, explain it yourself and directly. It is not a teachable moment and does not become one until [S027](/archive/bsc-programme/seminars/S027.md). *Residual risk the design accepts:* these students will be confused by anomalies more than others are, and the design's only answer is your direct explanation.

**A group predicts all five mixes.** Phase 3 is too easy for them by construction — three correct predictions is the design's expectation, not five. Give them the reserve sixth mix, chosen so the two representations they ranked adjacent swap under a small frequency change, and ask them to locate the crossover. It previews [S012](/archive/bsc-programme/seminars/S012.md) and it is hard.

**Calls to the endpoint fail, for one group or for all of them.** The day depends on a service, which is a failure mode its earlier form did not have. Move the affected groups onto the cached vectors and have them record the failure as an observation rather than an interruption; use the second deployment if the fault is configuration rather than the service. *Residual risk the design accepts:* a student whose calls failed will conclude something about the platform from a sample of one, and there is no framework for that here. Say the sample size out loud. That is the whole countermeasure.

**A student receives the P2 opening as a verdict on themselves.** The characteristic affective risk of this day sits in the opening rather than in the content: a badly wrong prediction, delivered alongside evidence of actual retention, reads as a judgement about capability rather than about human metacognition. Show the cohort distribution, which is uniformly poor and therefore makes the finding structural. Hold the two minutes of silence, so that no framing of yours arrives before the student's own. And honour the [S001](/archive/bsc-programme/seminars/S001.md) commitment to report the instrument's result whichever way it falls — including the case where the cohort's predictions were *accurate*, which is a finding against this design and is reported as one.

## Assessment

Specification item in CF102. The checked elements are: the logged operation mix; the committed cost predictions; the measurements taken from the built component; the mis-modelled-term reconciliation; the discarded-property statement with a named disqualified caller; **the prompt record**; **the intervention record**; and **the frontier statement**.

A prediction that matches the measurement exactly with no model stated fails the specification. An intervention record with no entries fails unless the build demonstrates that an intervention-worthy error would have been detectable.

**Nothing else is assessed.** In particular the agent's own output quality is not assessed, the phase 1 Copilot prediction is not assessed, and phase 3 case D is instruction rather than evidence.

## What this day does not establish

## What to take from this day

**The claim to hold.** **A representation discards in order to make something cheap.** Ask both halves, always — what did this discard, and what did it buy? Cost is per operation and choice is per operation mix, so the winner is the frequency-weighted sum rather than the row you were looking at. And **similar is a decision somebody made, not a property of text.**

**What the sources license, and what they do not.** The cost-model and representation-selection framing, and the physical causes of the constant factors deferred to [S016](/archive/bsc-programme/seminars/S016.md), are verified here, at [research/02-technical-foundations/jegou-product-quantization.md](/research/02-technical-foundations/jegou-product-quantization.md) and [research/02-technical-foundations/subramanya-diskann.md](/research/02-technical-foundations/subramanya-diskann.md). Metacognitive illusion, spacing, contrasting cases and prediction before adjudication are cited for **direction and mechanism only**, with no effect size asserted. The vendor documents the scoring transform and its bounds and publishes no retrieval accuracy; none is claimed here.

**Guidance for your own work.**

- **Derive the mix before you choose.** A representation ranked without frequencies is a preference wearing a cost model.
- **Write down the threshold you believe, then find out what the number it applies to actually is.** A synthetic monotonic transform is not the quantity you thought you were comparing.
- **Record a choice you cannot cheaply reverse as a bet**, in the [S007](/archive/bsc-programme/seminars/S007.md) sense, and state what would falsify it.
- **Name the defaults you did not set.** Model, vector width, wire format, similarity metric, and whether the server was read-only — each is a configured control, and the first of the five classes on the [Agent Configuration Standard](/archive/bsc-programme/program/13-Agent-Configuration-Standard.md) is the row that licenses nothing about what then happened.

**Where this is easy to get wrong.** Assuming the sophisticated representation is the good one. On at least one mix here the embedding is both the slowest and the wrong answer, and nothing about its sophistication warned you.
