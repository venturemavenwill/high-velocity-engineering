# S021 · Paradigms Are Hypotheses About Structure

**Module:** [M05](/archive/bsc-programme/modules/M05.md) · **Quarter:** [Q3](/archive/bsc-programme/quarters/Q3.md) · **Complexity class:** 2
**Strands:** CF · MS
**Whitepaper:** [WP-021](/archive/bsc-programme/whitepapers/WP-021.md)
**Depends on:** S008, S012
**Re-tests:** S014
**Platform anchor:** Azure AI Search — BM25, HNSW, exhaustive KNN and rank fusion over one index · **MCP servers:** Azure MCP Server (read) · Microsoft Learn MCP Server

---

## What this day is for

Divide and conquer, dynamic programming, greedy selection and backtracking are taught as techniques, and students learn to recognise which one a problem "is" by matching it against remembered examples. The matching works for problems that resemble the examples and fails otherwise, which is most of the time.

The day's target is that **each paradigm is a hypothesis about the problem's structure, and applying it is a claim that the structure holds.** Divide and conquer claims the subproblems are independent. Dynamic programming claims they overlap and the optimal solution is composed of optimal subsolutions. Greedy selection claims a locally best choice is globally safe. Each claim can be checked, and each is false for some problems that look like the ones where it is true.

S014 taught that recognising a problem's shape determines the algorithm. This day extends it: the shape also determines which *method* is legitimate, and using an illegitimate one produces a fast wrong answer.

**And today the fast wrong answer is not a diagram.** The cohort builds an Azure AI Search index over the substrate corpus and queries it four ways. One of those four ways is a greedy descent through a graph, one is an exhaustive scan of everything, and they are two configurations of the same field over the same vectors with the same distance metric. The greedy one is the default, it is fast, and it returns a full set of confident results for every query it is given — **including queries about things the corpus does not contain.** A method that cannot return nothing is a method whose hypothesis fails silently, and by the end of phase 3 the room has watched it happen.

## Phase 1 · Pretest and prediction (25 min)

Five items on substrate problems and the module's index.

1. A greedy algorithm is given for a scheduling problem, with a plausible justification. Does it produce an optimal answer?
2. Here is a counterexample-shaped input. Does it break it?
3. What property would the problem need for the greedy choice to be safe?
4. Predict: how many of the room found the break?
5. **Copilot prediction, sealed.** You will shortly ask the agent, in one instruction, to *build a search index over this corpus and configure retrieval so that results are relevant.* Write down what it will produce — which method it will choose, what it will claim about the result — and **name the one thing it will get wrong.** Sealed with items 1 to 4 and opened at phase 8.

Item 1's algorithm is wrong and looks right. Item 3 is the day's move. Item 5 is the day's contribution to the running frontier map, and the design's expectation is that most students will predict the agent chooses a hybrid configuration and asserts it is better, and that few will name the specific thing that makes the assertion unwarranted.

**Warrant.** Pretesting with a falsification demand. Item 2 provides the input rather than requiring its construction, which keeps the difficulty in the analysis rather than in the search. Item 5 is sealed at phase 1 and may not migrate into phase 5, per instrumentation rule 8: an instrument administered after its answer has been taught measures recall.

## Phase 3 · Contrasting cases and generation (45 min)

**Executed, not read.** Every group has the module's Azure AI Search index, a shared query set drawn from the substrate's own search logs, and an access token. They issue **the same queries four ways**, differing only in the method that selects the results.

| Case | Configuration | The structural property it asserts |
|---|---|---|
| **A** | Full-text only — BM25 over the text fields | The answer shares terms with the question |
| **B** | Pure vector — HNSW graph traversal over the embedding field | Nearness in the embedding space is relevance, **and greedy descent through the graph reaches the true nearest neighbours** |
| **C** | Hybrid — A and B fused by rank position | The two rankings are independent evidence, and position carries what matters |
| **D** | Pure vector — **the same field, the same vectors, the same metric, with `"exhaustive": true`** | Nothing. It compares the query against every vector |

Groups assign a paradigm to each case and, for each assignment, **state the structural property they are claiming holds**. They commit before running anything.

Then the queries are sent. Two rounds.

- **Round one, the substrate's real queries.** Groups record the returned identifiers and the scores.
- **Round two, three queries about things the corpus does not contain.** One nonsense string, one plausible question about a neighbouring domain, one question whose answer was deliberately removed from the corpus during indexing.

Task after: **state what distinguishes B from D**, in one sentence, in terms of the problem rather than of the configuration.

**Warrant.** Contrasting cases with near-identical surfaces and different deep structure, now executed against a metered service rather than supplied as data. B and D are the phase's payload and the contrast is as controlled as this module gets — one field, one embedding, one distance metric, one query, and **the only difference is whether the search is allowed to skip.** Most groups predict the two agree; where they do not, B's greedy-choice hypothesis has failed on the graph, and D is the only case in the room capable of showing it. Round two is the day's cheapest surprise: cases B, C and D return a full set of confident results for a query with no answer in the corpus, and case A returns nothing. Groups reach the day's central claim from that observation — a method that cannot say *no* is a method whose hypothesis fails silently — several minutes before phase 4 names it.

**One asymmetry is observed here and deliberately not explained.** Case D runs on the field configured for case B. The reverse does not work, and a group that tries it receives an error. Why is S023's subject and the day does not answer it.

## Phase 4 · Consolidating instruction (50 min)

1. **A paradigm is a hypothesis.** Applying it asserts a structural property; the assertion can be false and usually fails silently.
2. **The four hypotheses,** stated as checkable properties: independence of subproblems; optimal substructure with overlap; the greedy-choice property; exhaustive search with feasible pruning.
3. **How each fails.** Divide and conquer on dependent subproblems recomputes or corrupts; dynamic programming without optimal substructure gives a wrong optimum; greedy without the exchange property gives a plausible non-optimum; backtracking without pruning does not terminate usefully.
4. **The exchange argument,** worked, as the standard way to check the greedy-choice property. This is the day's one technique.
5. **Which hypothesis each phase 3 case asserted.** Case B is greedy selection: the graph traversal starts at an entry point and, at each level, moves to the candidate nearest the query, keeping a queue whose length is a configured parameter. Case D is exhaustive search with pruning removed. Case C is the independence claim — that two rankings produced by different methods are separate evidence about the same question. **Case A is not one of the four**, and the day says so: term-overlap scoring is a decomposable scoring function and the paradigm taxonomy does not cover it. **Three of the four hypotheses have an instance in front of you today and the fourth, dynamic programming, does not.** The taxonomy is not the world.
6. **What B and D differed by,** from phase 3, resolved. They differ by whether the greedy-choice property holds on the constructed graph. Where they returned the same set, it held on those queries. Where they did not, it did not — and no property of the query told you which case you were in.
7. **Cost, in M03's and M04's terms.** Dynamic programming trades memory for time and its table is a working set — S018 applies directly. The same trade is visible on the service: the graph traversal requires its data structures to be resident and consumes vector index quota, and the exhaustive scan requires no such structures and consumes none of that quota. **The approximation is paid for in memory and the exactness is paid for in time**, which is S012's decomposition on a bill.
8. **Defaults are opinions, and four were chosen for you before you typed a query.** The graph's bi-directional link count defaults to 4 on a range of 4 to 10; the neighbour count used during indexing defaults to 400 on a range of 100 to 1,000; the neighbour count used during search defaults to 500 on the same range; and **when you do not say how many results you want, you get fifty.** None of those was announced and each changes what phase 3 measured. An engineer who cannot state what was chosen for them does not understand their own system, and this generalises far beyond this vendor.
9. **What you owe when you cannot check the hypothesis.** State it as an assumption and say how you would detect its violation. S018's signal discipline, applied to correctness rather than to capacity. **On this service the detection signal is unusually cheap and unusually easy to omit**: the exhaustive configuration is available on the same field at query time, so a sampled comparison is a detection signal you can build in an afternoon, and almost nobody does.
10. **Why today's numbers are perishable and the reasoning is not.** Every parameter name, default and range above will change, and one of them is a value the vendor's own documentation annotates with an opinion — lower link counts are said to return less noise. **The structure is what is assessed and the number is not.** The correspondence between a greedy algorithm and a graph traversal is safe for reasoning about *why an approximate search can miss a document that exists*, and unsafe for reasoning about how often it does, about any other vector service by analogy, or about what would happen at a scale you have not run.

**Warrant.** Consolidation indexed to phase 3. Point 4 is the module's first proof technique and is worked completely because S023 depends on it. Point 5 is the day's scope statement delivered to students rather than to the whitepaper: the taxonomy is presented with the case it does not cover and the paradigm the service does not instantiate, which is the enumeration discipline the [Whitepaper Standard](/archive/bsc-programme/program/05-Whitepaper-Standard.md) requires. Point 8 is the platform-specific perishable content and satisfies the [Copilot Practice Standard](/archive/bsc-programme/program/12-Copilot-Practice-Standard.md)'s default-naming requirement; point 10 carries the strong-form scope statement.

## Phase 5 · Whole-task learning task (90 min)

**Class 2. The paradigm is not given. This phase produces a build.**

Students use Copilot in agent mode, through the Azure MCP Server in read configuration and the Learn MCP Server for grounding, to ship a **working retrieval configuration for one real substrate query class** — a class of question the substrate's users actually ask and the current system answers badly. They:

1. **State the structural properties** the query class does and does not have. Are the answers term-sharing? Are they paraphrases? Do they require two independent signals?
2. **Choose a method,** and state the hypothesis you are asserting. Any of the four phase 3 configurations, or another, or a composition.
3. **Check the hypothesis** — by exchange argument where the choice is greedy, by exhibiting the overlap where it is dynamic programming, by showing independence where you are combining rankings. **On this service the greedy check has an executable form:** run the same query set exhaustively on the same field and compare the returned sets.
4. **If the check fails, choose again** and record why.
5. **Build and measure,** with the configuration running against the real index and the real query set.
6. **State the input class** on which your hypothesis would fail, and whether the substrate can produce it.
7. **State the detection signal** for that failure, per point 9.

**The artefact carries three further elements**, per the [Copilot Practice Standard](/archive/bsc-programme/program/12-Copilot-Practice-Standard.md).

- **Prompt record.** The instructions you gave the agent, in order, including the ones you abandoned. Not a transcript — a record of what you asked for and why.
- **Intervention record.** Every point at which you corrected it, and what the correction was. **An intervention record with no entries fails**, unless the artefact demonstrates that your own design would have caught an intervention-worthy error — a sampled comparison against the exhaustive configuration is the obvious example and is accepted.
- **Frontier statement.** One thing the agent did faster than you could have, and one thing it did badly that you had to catch. Both specific, both from this build.

**Fading:** step 1 is worked with the room; step 3's exchange-argument template is supplied.

**Warrant.** Whole-task at class 2, now shipping a configuration rather than describing a choice. Step 4 makes a failed check a recorded event rather than a discarded attempt, which is the day's honesty requirement. Step 3's executable form is the design's principal gain from the platform anchor: the check that WP-021 predicted students would treat as ceremony is now a command whose output either matches or does not. Step 6 continues the module's input-class discipline.

## Phase 6 · Error clinic (40 min)

Instructor first: a substrate algorithm chosen for a structure the problem did not have, which produced answers that were wrong and plausible — with attention to how long it ran before anyone noticed and what made the wrongness invisible.

Then the agent case: a Copilot-generated retrieval configuration that was **confidently wrong and passed review**. Asked to build an index and make retrieval relevant, it produced a well-formed index, a hybrid query, a sensible chunking strategy and a short note saying the configuration would improve relevance. It was reviewed by two students and merged. It was wrong in a way neither of them looked for: **it never returned an empty result set.** Every query the substrate's users could ask returned a full page of confident, scored, plausible results, including the queries whose answers had been deleted from the corpus. Attention goes to why review did not catch it — the reviewers checked that results came back, the results looked reasonable, and *no output* was not on anyone's list of things to test for.

Then students: a method you applied because the problem looked like one you had seen, or a place today where you accepted agent output you had not checked.

**Warrant.** Error management. The instructor disclosure targets silent wrongness, which is the day's characteristic failure and the hardest kind to disclose because there is no crash to point at. The agent case is the [Copilot Practice Standard](/archive/bsc-programme/program/12-Copilot-Practice-Standard.md)'s required addition and is chosen so that the failure is invisible to the review the students would actually have performed: the artefact was correct against every check they knew to run.

## Phase 7 · Peer articulation (30 min)

Pairs. Each student states their step 2 hypothesis, and the partner's task is to **construct the input that violates it** — not to argue that it might be violated, but to produce a specific query, and to run it.

If they succeed, the student's step 4 is invoked.

**Warrant.** Interactive-tier articulation with a construction demand, which is the S006 breaking-caller discipline transposed from interfaces to algorithmic assumptions. Requiring the query to be run rather than described is new with the platform anchor and removes the phase's one weak outcome, which was a plausible attack nobody tested.

## When it does not work

These are [WP-021](/archive/bsc-programme/whitepapers/WP-021.md) §5's predicted failure modes, restated as instruction to the person in the room. The whitepaper is the authority; where this section and §5 diverge, §5 is right.

**A student with a competition-programming or strong algorithms background names every paradigm correctly and immediately, and never checks one.** Their pattern recognition is reliable, so step 3 reads as redundant. The clause that reaches them is stated in advance and applied without discretion: a paradigm choice with no hypothesis check fails the specification whether or not the choice was right. Point phase 7's partner at the *stated hypothesis* rather than at the choice, so that a correct choice with a vague hypothesis is still attackable. §5 also notes a second countermeasure that arrives free with the platform: their pattern recognition was trained on problems, not on a graph traversal over embeddings, and phase 3's B-against-D result is as new to them as to anyone.

**A student without that background meets the module's first new proof technique on the module's first day, alongside a new service.** Four supports exist and all four should be used rather than held back: point 4 works the exchange argument completely, step 3 supplies a template, step 3 accepts three alternative check forms — exhibit the overlap, or show independence, instead of arguing an exchange — and the index is built once for the module rather than per day. *Residual risk the design accepts:* they may choose the method they can check rather than the one the query class supports. Step 6 catches this partially and not reliably.

**Phase 3 is too easy, in its first half.** Case A's behaviour is predicted correctly by most groups and round two's result is legible on sight. The difficulty is the B-against-D discrimination, and it is robust because the two configurations are identical in every respect a student can see. If a group explains it, ask them to predict — before running it — which *kind* of query will show the largest divergence. That requires reasoning about where the graph's structure is thin and is genuinely hard.

**The check experienced as bureaucracy.** This is the day's characteristic disengagement and it is worst in the strongest students: they have selected correctly, implemented correctly and measured correctly, and are then asked to prove something they already believe. The paper version's countermeasure was argumentative; **the structural one is that the check is now a query parameter on a service they are already using**, so the question is not whether the ceremony is worth it but whether they ran it. §5 is explicit that whether that survives to phase 5 is the day's open question, and it is not settled.

**Agent-confidence adoption**, which §5 predicts will be common. A student who runs the agent before forming a view adopts its configuration and its confidence in one movement. Two structures prevent it and both must actually be enforced: item 5 is sealed before the agent is run, and groups commit their paradigm assignments in writing before any query is issued. Both work on the same mechanism — a written prior is harder to abandon than an unformed one — and both fail silently if the commitment is treated as a formality.

## Assessment

Specification item in CF103. Nothing else is assessed.

## What this day does not establish

**Demonstrated.** That configurations B and D can return different sets on this index, this embedding and this query set; that a query whose answer is not in the corpus returns nothing from the term-overlap case and a full page of scored results from the other three; and that the exhaustive query runs on the field built for the approximate one while the reverse is refused. All three are observations the room takes, and all three are about one corpus at one index size on one service version.

**Read rather than demonstrated.** Every parameter name, default and permitted range at point 8; the vendor's own annotation that lower link counts return less noise; and which quota the resident graph structures consume. These are documentation, read on the day, and point 10 marks them perishable for exactly that reason.

**Not established here, and not establishable here.** **How often the approximation misses.** The vendor publishes no recall figure at any parameter setting, on any corpus, at any index size, so there is no external number to compare the day's observations against — and the day's own measurements license nothing general, because they are a sample of one setting. A student who converts phase 3's observed divergence into a rate has done the thing [S028](/archive/bsc-programme/seminars/S028.md) exists to prevent.

**Asserted.** That a paradigm is a hypothesis about structure, that the four hypotheses are the ones worth checking, and that stating the structural property before running anything is what makes a check possible at all. This is the design's own reconstruction of a standard algorithms taxonomy; it rests on the argument made at point 1 and on nothing outside this repository. **Also asserted:** that the correspondence between greedy selection and graph descent is a correspondence of structure and not of magnitude. That is a scope claim the design makes about its own analogy, and point 10 states it to students rather than defending it.

**What rests on a `research/` note.** The late detection of quality regressions that produce no operational symptom, at [research/05-fde-craft/collected-materials.md](/research/05-fde-craft/collected-materials.md); the algorithmic and cost material, at [research/02-technical-foundations/malkov-yashunin-hnsw.md](/research/02-technical-foundations/malkov-yashunin-hnsw.md). Productive failure, which phase 3 runs on, has a complete reading at [research/04-professional-formation/sinha-kapur-productive-failure.md](/research/04-professional-formation/sinha-kapur-productive-failure.md), and error management, which phase 6 runs on, has one at [research/04-professional-formation/keith-frese-error-management-training.md](/research/04-professional-formation/keith-frese-error-management-training.md).

**What rests on nothing.** The rest of the day's instructional machinery. **Pretesting, expanding-interval retrieval and contrasting cases have no note anywhere in this repository**, and neither does worked-example fading or the cognitive-load reasoning [WP-021](/archive/bsc-programme/whitepapers/WP-021.md) §3.1 uses to justify building the index once. Those four decisions carry phases 1, 2, 3 and 5 between them — which is most of the day — and they are cited for direction and mechanism only because there is nothing here to cite for more.

## What to take from this day

**The claim to hold.** **A paradigm is a hypothesis about the problem's structure, and applying it asserts that the structure holds.** The assertion can be false, it fails silently, and a method that cannot return nothing is a method whose failure you will never be shown.

**What the sources license, and what they do not.** The late detection of quality regressions without operational symptoms is verified in this repository at [research/05-fde-craft/collected-materials.md](/research/05-fde-craft/collected-materials.md), and the algorithmic and cost material follows [research/02-technical-foundations/malkov-yashunin-hnsw.md](/research/02-technical-foundations/malkov-yashunin-hnsw.md). Productive failure, contrasting cases and worked-example fading are cited for **direction and mechanism only, and no magnitude is asserted.** The vendor states no recall figure for the approximate algorithm at any parameter setting, on any corpus, at any index size — **so nothing licenses a claim about how often the greedy hypothesis fails, and this day makes none.**

**Guidance for your own work.**

- Write down the structural property you are asserting before you run anything.
- Where the platform gives you an adjudicator, make the check a command rather than a paragraph.
- Record the check that failed. A discarded attempt is evidence you paid for and threw away.
- **Sort your conclusions into the five classes** on the [Agent Configuration Standard](/archive/bsc-programme/program/13-Agent-Configuration-Standard.md). *Results came back* is an observed result; *relevance improved* is an unsupported inference until something compares the sets.

**Where this is easy to get wrong.** Reading a full page of confident, scored, well-ordered results as evidence that the corpus contained an answer. Nothing in the form of the output distinguishes the query that had one from the query that did not.
