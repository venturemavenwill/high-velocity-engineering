# S027 · Error Has Structure

**Module:** [M06](/archive/bsc-programme/modules/M06.md) · **Quarter:** [Q3](/archive/bsc-programme/quarters/Q3.md) · **Complexity class:** 2
**Strands:** ME · MS · SY
**Whitepaper:** [WP-027](/archive/bsc-programme/whitepapers/WP-027.md)
**Depends on:** S026
**Re-tests:** S019, S022
**Platform anchor:** Microsoft Foundry evaluators as a measuring instrument with its own error structure · **MCP servers:** Microsoft Learn MCP Server · Azure MCP Server (read)

---

## What this day is for

Students who accept that measurements vary treat all variation as noise: something to average away, something more samples will fix. That belief is comforting and mostly false.

Most measurement error is **structured**. It has a source, the source has a mechanism, and the mechanism determines what — if anything — reduces it. A systematic offset does not shrink with more samples. A drift makes early and late observations incomparable. A selection effect makes the sample the wrong sample regardless of its size. Only the genuinely random component behaves the way students expect, and it is frequently the smallest term.

Yesterday's instrument was an evaluator. **Today that evaluator is the thing being measured.** It is a language model prompted to produce a score, which means it is non-deterministic, it has documented biases, its behaviour changes when the deployment behind it changes, and the platform silently drops evaluation runs when an hourly cap is reached. All four error sources are present in one instrument, they are all reachable in an afternoon, and three of them are invisible in the results file.

The target: **decompose the error before deciding what to do about it, because the remedy depends entirely on the source.**

## Phase 1 · Pretest and prediction (25 min)

Five items on a measurement of the module's substrate property, taken repeatedly.

1. The measurements vary. What would reduce the variation?
2. Here are the measurements grouped by time of day. What do you now think?
3. Here they are grouped by which machine took them. What do you now think?
4. Predict: would a hundred times more samples give you the true value?
5. **Copilot prediction, sealed.** You will shortly tell the agent that *your evaluation scores are inconsistent — fix it*. Write down what it will do, and **name the one thing it will get wrong**. Opened at phase 8.

Item 1's answer is almost always "more samples." Item 4's answer is no, and the reason is items 2 and 3.

Item 5's expectation is that the agent will raise the repetition count and average — which is the room's own item 1 answer, produced by a machine, and which fixes exactly one of the four sources present.

**Warrant.** Pretesting with sequential disclosure. Each item adds a grouping and defeats the previous answer, so the day's structure is produced by three revisions of the student's own position within twenty-five minutes. Item 5 is sealed here and may not migrate into phase 5, per instrumentation rule 8.

## Phase 3 · Contrasting cases and generation (45 min)

**Executed, not read.** Groups take **one evaluation** — the same evaluator over the same response set — and run it under four conditions, keeping every raw result.

| Condition | Set-up | What dominates |
|---|---|---|
| **A** | The identical batch, submitted repeatedly with the repetition count raised | Random variation — the judge is a model and does not return the same score every time |
| **B** | Two response sets carrying the **same information**, one terse and one expansively worded | A systematic offset — the longer set scores higher, every time, in the same direction |
| **C** | The same batch scored against **two judge deployments** of different model versions | Drift — today's scores and last month's are not measurements of the same thing |
| **D** | A large continuous-evaluation window whose results are read from the dashboard | A selection effect — the results file is complete, consistent and missing rows |

For each, groups state the dominant source and what they would do about it, and commit. Then the ground truth is supplied for each condition.

Task after: **for the condition you got wrong, state what in the data should have told you.**

**Condition D defeats most groups, because the missing observations are not in the data.** The mechanism is documented and unremarkable: continuous evaluation runs at a set sampling rate with a cap on evaluation runs per hour, and **when the cap is reached, runs are skipped**. The default is a hundred runs an hour. Skipped runs produce no row, no error and no gap in the numbering. The hours that hit the cap are the busy hours, so the results describe the system's quiet periods and say nothing about the periods anyone cares about. Nothing in the output reveals this and no amount of scrutiny of the recorded rows will.

Condition B is the day's cheapest surprise and the one that transfers furthest, because it is the same shape as the verbosity bias the research literature identifies in language-model judges independently of any vendor.

**Warrant.** Contrasting cases across error sources with a fixed measurement, now executed against the instrument the quarter runs on rather than supplied as a data file. Condition D is the payload — the diagnostic evidence is absent by construction, which is what makes selection effects the hardest class — and it is stronger here than in any constructed dataset because the students can read the documented cap that caused it and still not see its effect in their own results.

## Phase 4 · Consolidating instruction (50 min)

1. **Error decomposition.** A measurement is the true value plus contributions from distinct sources, and the sources behave differently.
2. **Four sources and what each does:** random variation, which averages out; systematic offset, which does not; drift, which makes observations non-comparable; selection, which makes the sample the wrong sample. **This list is not exhaustive. It omits interaction between sources, error introduced by the measurement itself, and error in the recording rather than the observation. All three are real; the first is taken up at S029, the second at S068, the third nowhere in this programme. These four cover what students can diagnose from data they have.**
3. **Why more samples is the wrong reflex.** It fixes exactly one of the four, and it is often the smallest.
4. **Diagnosis from data:** what grouping, ordering and comparison reveal, and what none of them reveal — which is condition D.
5. **The error budget** as an artefact: sources listed, magnitudes estimated, dominant one identified, remedy attached to each.
6. **What you do about each source** — and the honest entry, which is "nothing; this is a stated limitation."
7. **Precision and accuracy,** distinguished, and why a precise measurement can be confidently wrong.
8. **The S026 connection.** A construct-instrument gap is a systematic error you cannot see in the data at all, because the instrument is behaving correctly.
9. **The agent has the same error structure, and this is the point of the day you will use most.** Copilot's output varies between runs — that is condition A, and running the prompt again is a legitimate remedy for it. **Everything else about the agent's behaviour is condition B.** A prompt that biases it toward a particular library, a house style it learned from a corpus, a habit of accepting the first plausible schema mapping: none of these average out, and **asking more times makes you more confident in the same wrong thing.** This is the mechanism behind [S026](/archive/bsc-programme/seminars/S026.md)'s error clinic case, where the agent mapped `context` to the wrong field consistently, across every run, and repetition would have confirmed it. The remedy for a systematic component is a changed instrument — a changed prompt, a changed instructions file, a check the agent cannot talk its way past — and never a larger sample of the same instrument.
10. **Defaults are opinions and thresholds are policy.** Three chose for you today. **The evaluation-run cap defaults to a hundred an hour and its remedy for exceeding it is silent skipping**, not an error. Continuous evaluation samples at a rate you set and, if you did not set one, at the rate somebody else chose. And the judge model is a parameter: your score depends on which deployment you named, and nothing in the score records which one it was.
11. **What is perishable here and what is not.** The hundred-runs-an-hour cap, the sampling defaults and the current judge model families are perishable and will move. **The durable claim is that a measurement system with a capacity limit and a silent overflow policy manufactures a selection effect**, and that this is a property of the design and not of the vendor. Any queue that drops work under load and reports only what it processed does the same thing, which is why S019's contention material and this point are the same finding at different scales.

**Warrant.** Consolidation indexed to phase 3's four conditions. Point 2 carries the scope statement. Point 8 keeps the module's two ideas joined rather than parallel. **Point 9 is the [Copilot Practice Standard](/archive/bsc-programme/program/12-Copilot-Practice-Standard.md)'s commitment for this day** and is reachable from condition B's artefact, per instrumentation rule 7 — the students have just watched a systematic offset survive repetition in a judge, and the transfer to the agent is one step. Points 10 and 11 are the required platform default and perishability content.

## Phase 5 · Whole-task learning task (85 min)

**Class 2. The error budget is the student's. This phase produces a build.**

Students take their S026 instrument, apply it to the module's question, and — working through Copilot in agent mode — **ship an evaluation harness that records its own error structure**. They:

1. **Take the measurement,** repeatedly, under conditions you choose and record.
2. **Build the error budget** from point 5: every source you can name, with an estimated magnitude. **One entry is mandatory and is the agent's.** The harness in front of you was produced by Copilot; state its systematic component — a library it reaches for, a default it accepts, a mapping it makes without asking — estimate the magnitude of the effect on your number, and name the remedy. **"More prompts" is not a remedy and does not pass.**
3. **Identify the dominant source** and state the evidence.
4. **State what you did to reduce it,** or that you did not and why.
5. **Estimate the selection effect** — which observations did not get recorded, and how would you know. **Instrument the harness so that the answer is recoverable next time:** count what you submitted, count what came back, and report the difference.
6. **State the residual error** you are reporting with the measurement.
7. **State what the measurement would look like** if your dominant-source diagnosis were wrong.

Step 5's second half is the day's build. A harness that reconciles submitted against returned turns condition D from an undiagnosable class into a detectable one, and it is roughly four lines. **That the platform does not do this for you is the point**, and it is the cheapest instance in the programme of a countermeasure that costs almost nothing and is almost never in place.

**The artefact carries three further elements**, per the [Copilot Practice Standard](/archive/bsc-programme/program/12-Copilot-Practice-Standard.md).

- **Prompt record.** The instructions you gave the agent, in order, including the ones you abandoned.
- **Intervention record.** Every point at which you corrected it, and what the correction was. **An intervention record with no entries fails**, unless the artefact demonstrates that the design could have detected an intervention-worthy error — step 5's submitted-versus-returned reconciliation is exactly such a demonstration and is accepted.
- **Frontier statement.** One thing the agent did faster than you could have, and one thing it did badly that you had to catch.

**Fading:** step 2's budget template is supplied; step 5 is worked with the room.

**Warrant.** Whole-task at class 2 continuing from S026's instrument. Step 5 requires reasoning about absent data, which is the day's hardest demand, and its instrumentation half converts that reasoning into a shipped countermeasure. Step 7 is a falsification requirement applied to a diagnosis rather than to a claim.

## Phase 6 · Error clinic (40 min)

Instructor first: a substrate measurement that was averaged over a long window and concealed a drift, so that the reported figure was correct and described a system that no longer existed — with attention to how long the window had been in place and who chose it.

Then the agent case. A student asked Copilot to *make the evaluation more reliable*. It did what the room did at item 1: raised the repetition count from one to five and averaged. The variance in the reported figure fell visibly, the harness ran five times as long and cost five times as much, and **the number moved toward the same wrong value with greater confidence**, because the dominant source was the verbosity offset from condition B and repetition does nothing to it. The change was reviewed and approved. Attention goes to why: the reviewer checked whether the change was correctly implemented, which it was, and there was no place in the review where anyone was required to state which error source the change addressed.

Then students: variation you attributed to noise.

**Warrant.** Error management. The disclosure's attention to the window's provenance is the phase's content: aggregation choices are inherited and are rarely revisited. The agent case is the required addition and is chosen because the agent's answer is the cohort's own answer — the failure is not that the machine was stupid but that it was exactly as reflexive as the room was ninety minutes earlier.

## Phase 7 · Peer articulation (30 min)

Pairs. Each student presents their step 3 dominant-source diagnosis, and the partner's task is to **argue for a different source** using the same data.

Where the partner succeeds, the pair states what additional observation would settle it — and whether it can be taken.

**Warrant.** Interactive-tier articulation with a competing-explanation demand. The settling-observation question is the design's first informal encounter with experimental design and prepares S029.

---

## Phase 8 · Calibration and commitment (20 min)

- Items 1 to 4 resolved: how the room's item 1 answer changed across the sequence.
- The room's phase 3 condition D diagnoses shown against ground truth.
- **Item 5 opened.** The sealed Copilot predictions are read against what the agent actually did, in two bands: predicted *some* error, and named *repetition against a systematic source* specifically.
- Each student names one measurement they trust whose selection effect they have never considered.
- Retrieval schedule: next morning, day 3, week 2, week 6.

## When it does not work

These are [WP-027](/archive/bsc-programme/whitepapers/WP-027.md) §5's predicted failure modes, restated as instruction to the person in the room. The whitepaper is the authority; where this section and §5 diverge, §5 is right.

**A student with laboratory or experimental background already holds systematic against random and will clear conditions A to C.** Their predicted failure is condition D, which they will diagnose as an unusually large systematic offset — because their training supplies three of the four categories and selection effects belong to a different tradition. **Reveal condition D's ground truth with the missing observations shown**, which is unanswerable, and then ask the phase's closing question. For condition D the honest answer to *what in the data should have told you* is **nothing**, and that is the lesson rather than a failure of attention.

**A student without that background has to estimate four magnitudes at step 2 with no statistical apparatus.** Three supports exist: the budget template, phase 3's ground truth as a calibration reference, and the explicit acceptance that estimates are order-of-magnitude. *Residual risk the design accepts:* step 5's counterfactual reasoning may be unreachable. **The fallback is to state the recording mechanism and name one class of observation it would miss**, which is weaker and passes.

**Conditions A, B and C are diagnosed correctly by most groups inside twenty minutes, and that is intended** — the pattern must form before D violates it. Do not accelerate them. If a group diagnoses D as well, ask them to construct a fifth condition in which two sources are equally dominant and the standard remedies conflict; that is hard and previews the interaction case the day deliberately omits.

**The noise reflex replaced by paralysis.** This is the module's fatalism risk in its second form: a student who has learned that sampling fixes one source in four, and that one source cannot be diagnosed at all, concludes that no measurement can be trusted. Three countermeasures and all three are in the day — point 6's remedies **including the honest do-nothing entry**, step 6's residual-error statement, which is a constructive output rather than a disclaimer, and phase 3's ground truth, which shows that correct diagnosis is achievable in three of four cases. **The design's position is unchanged from [S026](/archive/bsc-programme/seminars/S026.md): this risk peaks in the module's first half and should resolve at [S029](/archive/bsc-programme/seminars/S029.md).**

**And the failure the day cannot label as a student failure.** The phase 6 agent case is the room's own item 1 answer, produced by a machine. When a student objects that the agent did the reasonable thing, agree — it did, and so did they, ninety minutes earlier. The point is not that the machine was stupid but that repetition against a systematic source moves you toward the same wrong value with more confidence, and that the change reviews cleanly because it was implemented correctly.

## Assessment

Specification item in ME101. Checked elements: the repeated measurement with recorded conditions; the error budget with estimated magnitudes **including the mandatory agent entry with its remedy**; the dominant source with evidence; the reduction attempted or declined with reasons; the selection-effect estimate **with the submitted-versus-returned reconciliation shipped**; the residual error; the diagnosis-falsification statement; **the prompt record**; **the intervention record**; **the frontier statement**.

**An error budget containing only random variation fails the specification.**

**An error budget with no agent entry fails the specification**, and *more prompts* does not count as the remedy on that entry.

**An intervention record with no entries fails**, unless the artefact demonstrates that the design could have detected an intervention-worthy error.

Nothing else is assessed.

## What this day does not establish

**Demonstrated.** That a judge does not return the same score every time on an identical batch; that the more expansively worded of two sets carrying the same information scores higher, in the same direction, every time; that two judge deployments of different model versions do not produce comparable scores; and that a results file can be complete, consistent, correctly numbered and missing rows. The last is the phase's payload and it is demonstrated only because the ground truth is supplied — **nothing in the recorded rows reveals it, which is the whole of the lesson.**

**Read rather than demonstrated.** The evaluation-run cap and its silent-skip policy; the continuous-evaluation sampling defaults; and the fact that the judge model is a parameter whose identity is not recorded in the score. All documentation, read on the day.

**Not established here, and not establishable here.** **The magnitude of any of the four sources.** The documentation publishes no figure for the size of the non-deterministic component, and condition B establishes a *direction* — which is, in the day's own words, the whole of what it claims. **No effect size is asserted for the verbosity offset, for the judge's variance, or for the drift between deployments**, and the day's own measurements are one corpus, one evaluator and one pair of deployments. A student who leaves with a number rather than a direction has taken more than the day gave.

**Asserted.** That these four sources are the right four — point 2 says the list is not exhaustive and names three omissions, one of which is taken up nowhere in this programme. And **point 9's transfer**: that everything about the agent's behaviour beyond run-to-run variation is a systematic component. That is the design's own argument by analogy from condition B; it is the most operationally useful claim on the page and it rests on the reasoning at point 9 rather than on a source.

**What rests on a `research/` note.** Error structure, systematic bias, drift and selection effects, at [research/03-measurement-evaluation/miller-adding-error-bars-to-evals.md](/research/03-measurement-evaluation/miller-adding-error-bars-to-evals.md) and [research/03-measurement-evaluation/singh-leaderboard-illusion.md](/research/03-measurement-evaluation/singh-leaderboard-illusion.md). **The first is a complete reading of the full text, with derivations, and it is the strongest citation this module has.** That a language-model judge shows a verbosity bias is recorded at **abstract-verification depth only** and carries direction and mechanism, nothing more. Error management, which carries phase 6, has a complete reading at [research/04-professional-formation/keith-frese-error-management-training.md](/research/04-professional-formation/keith-frese-error-management-training.md).

**What rests on nothing.** Pretesting with sequential disclosure — the phase 1 structure in which each item defeats the previous answer — has **no note anywhere in this repository**, and neither do expanding-interval retrieval, contrasting cases or worked-example fading. The sequential-disclosure construction is the day's principal instructional invention and its argument is [WP-027](/archive/bsc-programme/whitepapers/WP-027.md)'s own.

## What to take from this day

**The claim to hold.** **Most measurement error is structured, and the remedy depends entirely on the source.** More samples fixes exactly one of the four, and it is frequently the smallest. A systematic offset survives repetition, a drift makes early and late observations incomparable, and a capacity limit with a silent overflow policy manufactures a selection effect that is not visible in the rows you hold.

**What the sources license, and what they do not.** Error structure, systematic bias, drift and selection effects are verified in this repository at [research/03-measurement-evaluation/miller-adding-error-bars-to-evals.md](/research/03-measurement-evaluation/miller-adding-error-bars-to-evals.md) and [research/03-measurement-evaluation/singh-leaderboard-illusion.md](/research/03-measurement-evaluation/singh-leaderboard-illusion.md). That a language-model judge shows a verbosity bias is recorded at abstract-verification depth and is cited for **direction and mechanism only; no magnitude is asserted, and condition B establishes direction, which is the whole of what this day claims.** The documentation publishes no figure for how large the non-deterministic component is.

**Guidance for your own work.**

- Decompose before you remedy. Name the source, then choose the fix.
- Reconcile what you submitted against what came back. It is a few lines, and it turns an undiagnosable class into a detectable one.
- Give the agent an entry in your error budget. *More prompts* is not a remedy for a systematic component.
- **Pin the revision, host and model.** A judged score depends on the deployment you named and records nothing about it; the [Agent Configuration Standard](/archive/bsc-programme/program/13-Agent-Configuration-Standard.md) requires that dependency to be written down beside the result.

**Where this is easy to get wrong.** Reading reduced variance as improved accuracy. Repetition against a systematic offset moves you toward the same wrong value with more confidence, and the change reviews cleanly because it was implemented correctly.
